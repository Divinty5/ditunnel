# Di-Tunnel

Di-Tunnel — VPN-клиент для Windows 10 (версия 2004 и новее) и Windows 11. Он направляет системный трафик через Xray-core и TUN, управляет подписками, защищает соединение kill switch и поддерживает раздельное туннелирование.

![Значок Di-Tunnel](icon.png)

## Установка

1. Откройте [последний релиз](https://github.com/Divinty5/ditunnel/releases/latest).
2. Скачайте `Di-Tunnel-0.3.30-Setup-x64.exe` и файл контрольной суммы.
3. При желании проверьте установщик:

   ```powershell
   Get-FileHash .\Di-Tunnel-0.3.30-Setup-x64.exe -Algorithm SHA256
   ```

4. Запустите установщик и подтвердите запрос UAC.

Установщик уже содержит .NET Runtime, Xray-core и Wintun. Кодовая подпись пока отсутствует, поэтому Windows может показать предупреждение о неизвестном издателе. Повышенные права нужны для TUN, маршрутов, DNS и kill switch.

## Быстрый старт

1. Нажмите **+**.
2. Вставьте ссылку сервера, подписку или поддерживаемую конфигурацию.
3. Откройте **Подписки и профили** и выберите сервер.
4. Нажмите **Подключить**.

Подписки автоматически обновляются при запуске приложения. Di-Tunnel показывает последнюю измеренную задержку активного сервера и повторяет проверку каждые пять минут. Режим **Lowest** периодически проверяет все серверы и выбирает доступный сервер с наименьшей задержкой.

Для подключения поддерживаются:

- Hysteria 2;
- VLESS: TCP, WebSocket и HTTPUpgrade;
- Trojan;
- Shadowsocks SIP002.

VMess и произвольный Xray JSON можно импортировать и хранить, но подключение через них пока не реализовано. Профили сохраняются в `%LOCALAPPDATA%\DiTunnel` в файле, зашифрованном Windows DPAPI для текущей учётной записи.

## Kill switch

Kill switch блокирует прямой сетевой трафик, если защищённый туннель ещё не готов или неожиданно оборвался. Защита применяется одновременно к IPv4 и IPv6 через отдельные правила Windows Filtering Platform.

При потере сети Di-Tunnel сохраняет блокировку и пытается восстановить VPN до десяти раз с увеличивающейся паузой. Если восстановление не удалось, трафик остаётся заблокированным до ручного подключения или штатного отключения VPN. При необходимости в настройках можно разрешить доступ к локальной сети.

Статус **Kill switch активен** показывается только после подтверждения установки правил Windows. Обычное отключение удаляет только правила, принадлежащие Di-Tunnel.

## Раздельное туннелирование

В настройках доступны три режима:

- **Всё через VPN** — весь поддерживаемый системный трафик идёт через туннель;
- **Обход выбранных** — указанные домены или IPv4-адреса идут напрямую;
- **Только выбранные через VPN** — только указанные домены или IPv4-адреса идут через VPN.

Добавляйте по одному домену или IPv4-адресу в строке. URL `https://ifconfig.me/ip` будет преобразован в `ifconfig.me`. Поддомены учитываются автоматически, а изменившиеся IPv4-адреса доменов обновляются во время подключения.

Раздельное туннелирование приложений пока не реализовано. При активном kill switch прямой обход приложений также недоступен. Крупный сервис может использовать несколько доменов и CDN, поэтому одного домена иногда недостаточно.

## DNS, IPv4 и IPv6

Di-Tunnel не заменяет DNS-адрес физического адаптера. Системный маршрут направляет DNS-трафик через TUN, сохраняя исходную конфигурацию Windows для безопасного восстановления после отключения.

В Windows 11 VM проверены:

- одинаковый VPN-адрес для IPv4-запросов;
- VPN-адрес для IPv6;
- отсутствие DNS-серверов хоста в расширенном DNS leak test;
- блокировка IP-трафика при отключении физического адаптера;
- отсутствие прямого IP во время автоматического восстановления.

Проверка показала VPN-адрес и только резолверы Cloudflare в стране VPN-сервера. Результат всё равно зависит от конкретного сервера, профиля и конфигурации Windows.

## Управление профилями

- Выбор другого сервера при активном VPN вызывает безопасное переподключение.
- Активный профиль можно удалить: приложение предварительно переключится на оставшийся сервер с наименьшей известной задержкой.
- Подписку можно обновить или удалить из раздела **Подписки и профили**.
- Сетевые журналы не содержат подписок, ключей и паролей.

## Если подключение не восстановилось

Сначала попробуйте подключиться вручную. Если приложение сообщает, что очистка сети не завершена, закройте Di-Tunnel и запустите от администратора:

```powershell
.\scripts\Repair-DiTunnelNetwork.ps1
```

Скрипт удаляет только маршруты, DNS-политику и WFP-объекты Di-Tunnel. Он откажется работать при активном туннеле.

## Известные ограничения

- Выпускается только Windows x64.
- Установщик пока не подписан кодовой подписью.
- Нет раздельного туннелирования по приложениям.
- Нет рабочего подключения VMess и произвольного Xray JSON.
- Нет поддержки AmneziaWG.
- UI пока запускается с повышенными правами; отдельная Windows-служба запланирована на будущее.

## Разработка

Для сборки нужны .NET SDK 10.0.302+ и Windows SDK:

```powershell
dotnet restore
dotnet test DiTunnel.sln
dotnet build src\DiTunnel.Desktop\DiTunnel.Desktop.csproj -c Release
```

Установщик собирается Inno Setup:

```powershell
.\scripts\Build-WindowsInstaller.ps1
```

## Сторонние компоненты

Di-Tunnel распространяет закреплённую сборку Xray-core и Wintun. Их уведомления и лицензии включаются в установщик. Xray-core распространяется по MPL-2.0. Лицензия собственного кода Di-Tunnel пока не выбрана.
