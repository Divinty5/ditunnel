# Di-Tunnel

Di-Tunnel — VPN-клиент для Windows и Android на базе Xray-core и AmneziaWG. Приложение импортирует серверы и подписки, проверяет их доступность, переключает активный профиль и направляет трафик через системный VPN/TUN.

![Значок Di-Tunnel](icon.png)

## Поддерживаемые платформы

| Платформа | Минимальная версия | Релизный формат |
| --- | --- | --- |
| Windows x64 | Windows 10 2004 (build 19041) | `Di-Tunnel-<версия>-Setup-x64.exe` |
| Android ARM64 | Android 10 (API 29), включая проверенный HarmonyOS 2 | `Di-Tunnel-<версия>-arm64.apk` |

Подготовлена общая версия **0.5.13 для Windows и Android**; новые элементы списка приложений требуют ручной проверки. Пользователь подтвердил РТ Vivaldi в Windows 0.5.11, включая AWG 2.0, и восстановление после потери сети с долгим нажатием плитки в Android 0.5.12. Эти локальные сборки ещё не опубликованы отдельными GitHub-релизами. Linux остаётся в плане разработки и сейчас не является поддерживаемой платформой.

Android-сборка не зависит от Google Play Services. Сейчас выпускается только для `arm64-v8a`; ARM32 и универсальный APK не публикуются.

## Установка

Откройте [список релизов](https://github.com/Divinty5/ditunnel/releases), найдите последний релиз с файлом для своей платформы и скачайте его вместе с опубликованной SHA-256 checksum. Версии платформ выпускаются отдельно: Windows-релиз без APK не является обновлением Android.

На Windows запустите установщик и подтвердите UAC. В комплект уже входят .NET Runtime, Xray-core, AmneziaWG и Wintun. Пока установщик не подписан, Windows может показать предупреждение о неизвестном издателе.

Интерфейс Windows запускается с обычными правами. При первом подключении или проверке сервера отдельно запускается `Di-Tunnel.NetworkHost.exe` с запросом UAC. Сетевой модуль на C# управляет туннелем, маршрутами, DNS и kill switch без запуска PowerShell; при закрытии интерфейса он завершает восстановление сети самостоятельно.

PowerShell используется в служебных сценариях: подготовке ядер, сборке Windows/Android и запуске из исходников. `Repair-DiTunnelNetwork.ps1` поставляется как ручной инструмент восстановления сети и вызывает сетевой модуль C#; приложение автоматически его не запускает. Установщик также вызывает сетевой модуль напрямую при очистке. Отсутствие PowerShell в подключении VPN не гарантирует отсутствия срабатываний антивируса.

В настройках доступны русский, английский, испанский и упрощённый китайский языки. Язык выбирается в выпадающем списке и применяется сразу.

Windows-клиент автоматически проверяет новые GitHub-релизы при запуске. Установка выполняется только после подтверждения пользователя: клиент скачивает установщик и опубликованный файл SHA-256, проверяет контрольную сумму, штатно отключает VPN и запускает обновление с запросом UAC. Автоматическую проверку можно отключить в настройках.

Начиная с Windows 0.5.7 проверка ищет последнюю стабильную версию с установщиком и SHA-256 именно для текущей платформы, включая предыдущие страницы списка релизов. Релизы другой платформы, черновики и предварительные версии не предлагаются. Версии Windows и Android задаются отдельно в `Directory.Build.props`. Уже опубликованные клиенты используют общий GitHub latest: Windows-релиз, помеченный latest, вызовет уведомление и на старом Android без APK. Чтобы оставить Android без уведомлений, Windows 0.5.7 нужно опубликовать без изменения latest и установить вручную один раз.

На Android разрешите установку APK из выбранного источника. При первом подключении подтвердите системный запрос на создание VPN. В Android 0.5.10 реализован запуск системного Always-on из последней зашифрованной конфигурации. Сначала подключитесь вручную, затем включите Always-on и, при необходимости, «Блокировать соединения без VPN» в системных настройках VPN. Возврат после потери сети подтверждён на Android 0.5.12; запуск после перезагрузки и системный lockdown ещё требуют проверки на устройстве.

Проверка SHA-256 в PowerShell:

```powershell
Get-FileHash .\Di-Tunnel-<версия>-arm64.apk -Algorithm SHA256
```

## Быстрый старт

1. Нажмите **+**.
2. Импортируйте ссылку/подписку из буфера, QR-кода либо добавьте профиль вручную.
3. Откройте **Подписки и профили** и выберите сервер.
4. Нажмите **Подключить**.

Подписки можно обновлять вручную. Кнопка **Быстрая** выбирает короткую проверку, а результат указывает её фактический метод: на Windows HTTP через временный Xray либо TLS через AmneziaWG; на Android TCP, HTTP для Hysteria 2 либо Handshake для AmneziaWG. Измерение AWG Handshake включает запуск ядра. Точная проверка выполняет HTTPS-запрос через профиль. Режим **Lowest** периодически выбирает доступный сервер с минимальной измеренной задержкой.

Подключение поддерживает Hysteria 2, VLESS и VMess AEAD поверх TCP/WebSocket/HTTPUpgrade/gRPC, Trojan и Shadowsocks SIP002. VMess импортируется из Base64 JSON-ссылок `vmess://`; поддержаны `aid=0`, выбор шифрования, SNI, ALPN и TLS fingerprint. Проверка сертификата обязательна; устаревший VMess с ненулевым `aid` и неподдерживаемые транспорты отклоняются с пояснением. Произвольный Xray JSON пока можно только импортировать и хранить.

### AmneziaWG

AmneziaWG подключается на Windows и Android через закреплённое официальное Go-ядро. TCP/UDP передаются через сетевой стек в памяти; Xray обслуживает системный TUN, доменные правила и блокировку рекламы. Второй системный адаптер AWG и отдельное приложение AmneziaVPN не требуются.

Импортируются клиентские `.conf`, Base64 и ссылки AmneziaVPN `vpn://` с готовой конфигурацией. На Windows дополнительно доступно **+ → Из файла**. Поддерживается один Peer; командные хуки, неизвестные поля, plain WireGuard и доступ к управлению сервером без клиентской конфигурации отклоняются. Версия протокола берётся из экспорта либо определяется по полям, ключи хранятся в защищённом платформенном хранилище.

| Возможность | Windows 0.5.13 | Android 0.5.13 |
| --- | --- | --- |
| AWG, TCP/UDP, DNS, MTU и AllowedIPs | Реализованы | Реализованы |
| Блокировка рекламы и доменные/IP-правила | Через Xray | Через Xray |
| Разделение по приложениям | Список .exe, правила Xray по процессам; Vivaldi проверен, полный WFP-прогон требуется | Списки приложений Android |
| Внешний endpoint | IPv4 | IPv4/IPv6 |
| Внутренний IPv6 | При Address/AllowedIPs и поддержке сервера | При Address/AllowedIPs и поддержке сервера |
| Быстрая / точная проверка | TLS / HTTPS | Handshake / HTTPS; активный профиль — HTTPS |
| Плитка и виджеты | Не применимо | Переключение VPN и выбор сервера |

AWG 2.0 проверен пользователем на Android 16 ARM64: импорт, подключение, обе проверки, внешний IP, работа приложений и блокировка рекламы. В 0.5.9 исправлена ошибка IPv6 у профиля IPv4; Vivaldi успешно открывает chatgpt.com, что подтверждено NetLog. На Windows пользователь также подтвердил открытие сайта через AWG. Реализация остальных параметров AWG не означает, что каждый вариант и системный сценарий уже проверен на устройстве.

Исправлены выбор handshake-адреса и DNS для IPv6, объявление семейства TUN Windows и блокировка неподдерживаемого семейства до split-правил. Остаются проверки утечек, восстановления, Always-on и аварийного завершения на устройствах. Все ограничения и доказательства собраны в [проверке поддержки AWG](docs/amneziawg-support-review.md). Архитектура: [интеграция AWG](docs/amneziawg-integration.md), [Android-протоколы и управление](docs/android-controls-and-protocols.md).

На Windows быстрая массовая проверка запускает до восьми профилей параллельно; на DNS отводится до 4 секунд, на сетевую проверку — до 8 секунд. Точная HTTPS-проверка сохраняет сетевой бюджет 12 секунд. Значение задержки — время контрольного запроса через прокси, а не ICMP ping. Обычные профили одного IP разделяют маршрут без очереди; AWG проверяется последовательно для одного endpoint. При активных правилах kill switch проверки сохраняют очередь для общего временного разрешения WFP. Без активных правил этот слот не резервируется. Каждый профиль пока использует отдельный временный процесс Xray.

## Хранение данных

На Windows профили хранятся в `%LOCALAPPDATA%\DiTunnel` и шифруются DPAPI текущего пользователя. На Android данные находятся во внутреннем каталоге приложения, защищены Android Keystore и исключены из резервного копирования. Удаление Android-приложения удаляет его локальные подписки и настройки.

## Защита соединения

Windows kill switch использует собственные правила Windows Filtering Platform для IPv4 и IPv6. Они сохраняются во время восстановления VPN и удаляются при штатном отключении.

Windows 0.5.10 проверяет собственные блокирующие фильтры, оставшиеся после сбоя, и показывает блокировку даже без активного VPN. При намеренно включённом kill switch авария сохраняет fail-closed защиту, в том числе после перезагрузки. Для явного отключения используйте «Настройки → Диагностика → Восстановить доступ к сети» с подтверждением UAC. Команда останавливает VPN и удаляет только WFP/DNS-объекты Di-Tunnel. Отключение настройки kill switch также освобождает оставшуюся блокировку при возврате на главный экран.

В Android 0.5.10 включена поддержка системного Always-on VPN. Сервис использует Sticky и восстанавливает последнюю конфигурацию из хранилища, зашифрованного Android Keystore, без зависимости от открытого интерфейса. Перезапуск после потери служебного процесса и смены сети реализован; автозапуск после перезагрузки требует включённого системного Always-on. Блокировку трафика во время восстановления обеспечивает системная настройка «Блокировать соединения без VPN», а не Sticky. Возврат после потери сети подтверждён в Android 0.5.12; reboot, lockdown и расширенные сценарии без UI требуют проверки на телефоне: [порядок ручной проверки](docs/awg-manual-validation.md).

При подключении, переподключении и проверке в меню подписок отображаются кнопки отмены над прокручиваемым списком. Отмена подключения остаётся видимой до завершения очистки. При переключении сервера работающий VPN переподключается. Простое открытие другой подписки не меняет активный профиль.

## Раздельное туннелирование

Доступны режимы **Всё через VPN**, **Обход выбранных** и **Только выбранные через VPN**. Домены и IPv4-адреса вводятся по одному в строке; URL автоматически приводятся к имени хоста. На обеих платформах можно отметить приложения в списке и снять все галочки одной кнопкой. Сброс затрагивает текущий режим, сохраняя домены и выбор другого режима. Windows собирает исполняемые файлы из меню «Пуск», App Paths, пакетов Store/MSIX и работающих приложений, поддерживает поиск и ручное добавление `.exe`. Автовыбор VPN включает ChatGPT/Codex и его CLI. При выборе процессов трафик захватывается TUN, затем правила Xray выбирают VPN или прямой выход; kill switch разрешает такой выход только процессу Xray. Пользователь подтвердил обход и проксирование Vivaldi, включая AWG 2.0; полный WFP-прогон ещё требуется. Пути WindowsApps и Codex CLI могут меняться при обновлении этих приложений: после обновления заново выполните автовыбор.

Android начиная с 0.5.11 восстанавливает VPN через отдельный foreground-контроллер, который ждёт возвращения физической сети и явно пересоздаёт нативный процесс. При обычной потере сети процесс больше не завершается в надежде на Sticky-перезапуск ОС. Пользователь подтвердил восстановление и открытие приложения долгим нажатием плитки в 0.5.12. Проверки обновления приведены в [сценарии 5 октября](docs/controls-recovery-validation.md).

Опция **Блокировать рекламу и трекеры** действует на Windows и Android: Xray сверяет домены с локальной категорией `category-ads-all` из закреплённой базы `geosite.dat` и отклоняет совпавшие соединения. Это блокирует многие рекламные и аналитические сети в браузерах и приложениях, но не гарантирует удаление рекламы YouTube: видео и реклама YouTube могут загружаться с одних и тех же доменов, которые нельзя заблокировать целиком без поломки воспроизведения.

## DNS и проверка утечек

Для прежнего сетевого модуля Windows в изолированной VM подтверждены VPN-выход IPv4/IPv6, отсутствие DNS хоста и блокировка прямого трафика при потере сети. Новый модуль на C# требует повторного системного прогона; прежние результаты не считаются его сетевой валидацией. На Android ARM64 подтверждены VPN-адрес и только DNS-резолверы Cloudflare в стране VPN-сервера. Результат зависит от профиля, сервера, ОС и выбранных правил маршрутизации.

Подробнее: [Windows TUN/DNS validation](docs/windows-tun-validation.md) и [Android release validation](docs/android-release-validation.md).

## Восстановление Windows

Если приложение сообщает, что очистка сети не завершена, закройте Di-Tunnel и запустите от администратора:

```powershell
.\scripts\Repair-DiTunnelNetwork.ps1
```

Скрипт удаляет только DNS-политику и WFP-объекты Di-Tunnel и отказывается работать при активном туннеле. Маршруты штатно удаляются сетевым модулем при отключении; скрипт не удаляет маршруты физического адаптера.

## Известные ограничения

- Windows installer пока не подписан кодовой подписью.
- Android-релиз выпускается только для ARM64; APK скачивается вручную либо через обновление в приложении, а установка подтверждается в системном установщике.
- Произвольный Xray JSON только хранится. AWG 2.0 проверен на Android; остальные варианты и полный системный прогон AWG остаются в матрице проверки.
- Android Always-on после перезагрузки, расширенные сценарии восстановления без интерфейса и системный lockdown требуют ручной проверки 0.5.13; возврат после потери сети подтверждён в 0.5.12. Без системного lockdown возможен прямой трафик во время перезапуска VPN. Windows AWG требует IPv4 endpoint.
- Hysteria 2 использует UDP/QUIC, поэтому проверяется медленнее и сильнее зависит от качества сети.
- Сетевой модуль Windows требует UAC; интерфейс работает с обычными правами. Обычное подключение и РТ по приложениям подтверждены пользователем; полный прогон аварий, WFP и совместимости с корпоративной защитой ещё требуется.

## Разработка

При сборке Windows-версии из исходников `Build-AmneziaWG.ps1` автоматически скачивает закреплённую версию Go для сборки компонента AmneziaWG. `Start-DiTunnel.ps1` также выполняет эту сборку перед запуском. Для запуска приложения из готового Windows-установщика Go не требуется.

Требуются .NET SDK `10.0.302+` и соответствующие workloads:

```powershell
dotnet restore
./scripts/Build-AmneziaWG.ps1 -Test
dotnet test DiTunnel.sln
dotnet build src\DiTunnel.Desktop\DiTunnel.Desktop.csproj -c Release
./scripts/Build-Android.ps1 -RuntimeIdentifier android-arm64
```

Для Android требуются закреплённые libXray, нативный мост `libditunnel-awg.so`, Android SDK/NDK и JDK. `Build-Android.ps1` проверяет комплект runtime; корень AWG-библиотек задаётся `DITUNNEL_ANDROID_AWG_ROOT`. Локальный workflow находится в игнорируемом `.tools/android-build-local`; SDK, APK, ключ подписи и пароли в Git не входят. После утраты прежнего ключа новые тестовые APK подписываются новым ключом: обновление поверх APK со старой подписью невозможно без удаления старого приложения и его локальных данных. Соседние тестовые версии с новым ключом обновляются штатно.

## Сторонние компоненты

Windows распространяет закреплённый Xray-core `v26.3.27` и Wintun. Android использует закреплённый libXray `v26.7.28`. Версии, источники и SHA-256 записаны в `eng/`. Xray-core/libXray распространяются по MPL-2.0; сторонние уведомления включаются в релизные материалы. Собственный код Di-Tunnel распространяется по [лицензии MIT](LICENSE).

Windows-backend AmneziaWG собирается из Go-ядра с закреплённым commit `b5928efb6ca1` и зависимостей из `runtime/amneziawg/go.sum`. Go toolchain проверяется по SHA-256. Runtime, его checksum и лицензии копируются в `Runtime/AmneziaWG`; отдельная установка Amnezia VPN, службы или драйвера AWG не требуется. Сборка runtime выполняется также при запуске `Start-DiTunnel.ps1` и сборке Windows-установщика.
