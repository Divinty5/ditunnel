# Windows 0.6.5: проверки интерфейса и запуска

Дата: 17 октября 2026 года.

## Изменения

- Заголовок: перед сменой DWM theme обновляется кэш non-client оформления через `SetWindowTheme`; затем перерисовывается текущая рамка без `SWP_FRAMECHANGED`. Обновление повторяется при активации и восстановлении окна. Штатные кнопки, стили, HWND и размеры сохраняются.
- Значок: загрузка Microsoft PDB ограничена целиком, включая чтение HTTP body. Ошибка оставляет возможность повторить попытку в том же процессе. После подключения компонента заново создаётся реализация текущего значка, чтобы Win32 сбросил кэш даже при изменении состояния VPN до загрузки символов. Статусы подготовки/готовности/ошибки экспортируются в `taskbar-icon.log` без путей, подписок и адресов серверов.
- Автозапуск: пользовательский HKCU Run, команда с кавычками вокруг пути и `--autostart`, без дополнительных служб. Оба новых параметра выключены по умолчанию; запуск в свёрнутом виде доступен только при включённом автозапуске. Ручной запуск и повторный ручной запуск открывают окно. При недоступном трее остаётся обычное сворачивание. Удаление программы очищает только собственное значение Run пользователя, от имени которого выполняется деинсталляция; записи других учётных записей не затрагиваются.
- Сервер: выбор сохраняется по подписке в виде SHA-256 от содержимого и логической идентичности. Ссылка и ключи не попадают в JSON настроек. Сначала восстанавливается точное совпадение, затем сервер с прежними именем и протоколом при обновлении конфигурации; при удалении выбирается доступный сервер.

## Выполненные проверки

- 132 теста `DiTunnel.App.Tests`, включая зависший HTTP body, удаление частичного файла и успешную повторную загрузку; HY2 после перезапуска, смены подписки, обновления конфигурации и удаления сервера; регистрацию автозапуска с пробелами в пути и удаление только собственного значения в изолированном тестовом ключе.
- Тестам моделей выделен временный каталог настроек, чтобы они не меняли предпочтения установленного приложения.
- Native/UI smoke: темы DWM, границы окна, цвета HICON, позднее применение значка с новым HICON и теми же пикселями, сохранение HWND, размеров, фокуса и идентичности группы панели задач. Загрузка кода в Explorer в этих проверках отключена.
- Startup smoke: автоматический запуск свёрнут, ручной запуск видим, окно можно восстановить, тестовый трей освобождается. Реальная автозагрузка Windows не регистрировалась.
- В отдельном окне настоящего `MainWindow` через computer-use проверены светлая → тёмная темы, видимые штатные кнопки, разворачивание и закрытие. Обе галочки изначально выключены; зависимая галочка активируется и отключается вместе с автозапуском. Callback регистрации подменён, VPN не подключался, Explorer не изменялся.
- Собран self-contained установщик с полным runtime, проверены версии 0.6.5 и SHA-256 sidecar. На основной системе установщик не запускался.
- Дополнительно пройден целевой тест обезличивания нового `taskbar-icon.log` при экспорте диагностики.

Итоговый файл: `Di-Tunnel-0.6.5-Setup-x64.exe`, 76 682 898 байт. SHA-256: `8b6528cdf8ad8ee08f9dc552bf21da7d90a2ebfb9930908acc2cb7aaa83bad9e`. Компилятор Inno сообщил предупреждение о сочетании административной установки и HKCU: запись используется только для очистки собственного значения при деинсталляции, при установке значение автозапуска не создаётся. При вводе реквизитов другой административной учётной записи очистка не распространяется на исходного пользователя.

## Что требует проверки на других компьютерах

Изначальная ошибка заголовка на рабочем компьютере здесь не воспроизводилась. Исправление нужно повторно проверить на том компьютере, включая RDP и его графический драйвер, если они используются.

Зависание чтения символов и позднее применение значка воспроизведены детерминированными тестами. Причина поведения у коллеги без его диагностики не установлена. На первом запуске, после обновления Windows или очистки кэша подготовка значка может требовать доступа к Microsoft Symbol Server; при недоступном сервере компонент повторяет попытки. Мгновенная готовность на машине без кэша не обещается. Нужна повторная проверка у коллеги без перезапуска Di-Tunnel.
