# Di-Tunnel 0.6.9 — Windows, Android и Linux

Общий релиз от 9 ноября 2026: [v0.6.9 на GitHub](https://github.com/Divinty5/ditunnel/releases/tag/v0.6.9). Все платформы имеют версию 0.6.9; Android — versionCode 60009.

Релиз включает накопленные изменения после Windows/Android 0.6.4 и Linux 0.6.6: общие короткие сообщения проверок и подробности в копировании, ускоренную пакетную проверку Android, неподвижные приглушённые красные кнопки остановки/отмены, уведомления обновления на всех экранах, цвета квот и блокировку подключения при достоверном исчерпании подписки. В Windows сохранена совместимость с OpenVPN при выключенном kill switch; установщик оформлен в чёрно-фиолетовых цветах. [Подробности предыдущей подготовки](release-0.6.8-windows-0.6.7-mobile-linux.md).

## Исправление проверочного прокси

Каждый временный SOCKS-вход требует RFC1929: случайный логин (128 бит) и пароль (256 бит), отдельные для каждого профиля и запуска. Генератор отказывается создавать вход без учётных данных. Проверки готовности, HTTP/HTTPS и TLS используют тот же пароль без перехода к noauth. На Android учётные данные подготовленного профиля сохраняются при валидации и разделении неудачной группы. UDP проверочных входов выключен.

Windows/Linux передают проверочный JSON в Xray через анонимный stdin-канал (`run -config stdin: -format json`). Учётные данные не появляются в командной строке, временном JSON или новой диагностике; представление объекта учётных данных скрыто. Android передаёт JSON в памяти через существующий вызов libXray. Остановка и отмена сохраняют прежнее управление процессом.

Исправление охватывает обычные профили, предварительную проверку подключения, проверочную обёртку AWG на Windows/Linux и пакет Android. Быстрая TCP-проверка Android, рабочий TUN и отдельный AWG-мост не менялись. Защита не рассчитана на процесс, уже способный читать память DT; проверка отдельной UDP-гонки AWG в эту работу не входит.

## Общий заголовок Windows

Windows 10 и 11 используют `ExtendClientAreaToDecorationsHint` и штатные drawn decorations Avalonia 12.1.2 с полной системной рамкой. Отдельная реализация Windows 10 и BorderOnly удалены. Три стандартные кнопки рисуются библиотекой; лишняя кнопка полного экрана скрыта. Отступ страницы привязан к `WindowDecorationMargin`, длинный заголовок сокращается перед кнопками. DWM используется только для цвета оставшейся системной границы, без принудительной перерисовки управляемого заголовка. Linux и Android сохраняют своё оформление.

Основание — [Window Avalonia 12.1.2](https://github.com/AvaloniaUI/Avalonia/blob/12.1.2/src/Avalonia.Controls/Window.cs) и [штатный шаблон заголовка](https://github.com/AvaloniaUI/Avalonia/blob/12.1.2/src/Avalonia.Themes.Fluent/Controls/WindowDrawnDecorations.xaml).

## Проверки

- `AuthenticatedProbeRuntimeTests`: настоящий локальный Xray, синтетический VLESS и локальный HTTP-сервер. Вход без пароля и SOCKS4 отклоняются; неверные логин/пароль, пароль соседнего профиля и прежнего запуска не принимаются; правильный пароль передаёт HTTP через профиль. Проверяются обычный и Android-пакетный генераторы, HttpClientHandler и SocketsHttpHandler. Внешняя сеть не нужна.
- `ProbeSocksCredentialsTests`, `SocksListenerReadinessTests`, `SocksTcpProbeTests`: обязательные учётные данные, отказ понижения метода, некорректная версия/ошибка авторизации, фрагментированные ответы, TLS-валидация и отмена. Проверены раздельные пароли и их сохранение при разделении Android-группы.
- `VmessRuntimeTests`: штатная общая проверка проходит через локальный VMess без создания проверочного JSON. Метаданные TUN не меняются.
- `DiTunnel.Icon.Smoke --managed-caption`: восемь смен глобальной темы, контраст и центрирование значков, привязка текста, отступ страницы, отсутствие непокрытой полосы между верхом окна и клиентской областью, обычная отменяемая обработка закрытия, сохранение размеров и активации. Снимки светлой/тёмной темы просмотрены.
- Изолированная навигация на ширине 900/400: отмена/остановка не сдвигает блоки, уведомление остаётся видно на других страницах.
- Финальный набор Windows: 66 проверок Infrastructure.Xray, 105 тестов Platform.Windows и 157 тестов App; Linux: 66 проверок Infrastructure.Xray и 80 тестов Platform.Linux. Сценарии старых Windows-only тестов на Linux возвращаются без выполнения; оба новых native-сценария авторизации фактически выполняются на Linux с его упаковываемым Xray.

Автоматические проверки не меняли маршруты, DNS, WFP, системное хранилище сертификатов или состояние установленного VPN; ADB не запускался. 9 ноября пользователь подтвердил исправление заголовка на рабочем Windows 10 Pro 22H2 и работоспособность APK 0.6.8 на телефоне. Ранее подтверждены заголовок Windows 11 и совместная работа с OpenVPN в обоих порядках включения при выключенном kill switch. Android/Linux 0.6.9 подняты с 0.6.8 для общего релиза; новая версия не означает повторный прогон всей матрицы устройств. Продолжительный сон Huawei, reboot/lockdown и расширенные аварийные сценарии остаются отдельными проверками.
