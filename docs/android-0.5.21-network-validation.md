# Android 0.5.21: проверка определения физической сети

Неофициальный локальный APK; отдельный этап после проверки установки 0.5.20 на Android 8.1. Поддержка Android 8.1 ARM64 и target API 36 сохраняются. Общий релиз не публикуется.

## Наблюдения 8 октября 2026 года

- На телефоне владельца Android 0.5.19 не подключает AWG, HY2 и остальные профили; перед подключением появляется «Нет подключения к интернету», проверки серверов возвращают «Нет доступной физической сети». Пользователь сообщает, что интернет доступен; перезагрузка не помогла.
- Проверялось мобильное подключение. Wi-Fi пока недоступен для сравнительного испытания.
- Пользователь уточнил: Hiddify с той же подпиской тоже не работает. Это не позволяет отнести весь отказ к Di-Tunnel или только к телефону: остаются возможными ограничения сети оператора, недоступность серверов и настройки устройства.
- На телефоне друга тестовая 0.5.20 работает с подпиской из четырёх конфигураций, включая HY2, по сообщению владельца. Подробный прогон каждой конфигурации и фоновых сценариев отдельно не описан.

## Найденное ограничение и исправление

В 0.5.19 выбор физической сети и состояние доступности в callback требуют одновременно NOT_VPN, INTERNET и VALIDATED. Последний флаг означает успешную системную проверку доступа в интернет, а не доступность конкретного VPN-сервера. Если такой флаг отсутствует, приложение отказывает сразу всем протоколам ещё до их проверки.

В 0.5.21:

- Сеть с NOT_VPN + INTERNET разрешает попытку подключения и проверку сервера даже без VALIDATED.
- Сеть с VALIDATED остаётся предпочтительной. При равной проверенности предпочтение отдаётся активной сети Android.
- VPN-сети и сети без INTERNET по-прежнему исключаются; физические сокеты не заменяются сокетами VPN.
- Первичное подключение, проверки профилей и ожидание восстановления используют согласованные условия доступности. Потеря только отметки VALIDATED не считается отключением физической сети; потеря самой сети обрабатывается как раньше.
- AndroidVersion = 0.5.21, versionCode = 50021. WindowsVersion и LinuxVersion не меняются.

Это исправляет доказанное ограничение приложения. Наличие именно такого состояния на телефоне владельца пока не подтверждено системными журналами. Исправление не гарантирует доступ к серверам, если их блокирует оператор или они недоступны по другой причине.

Основание: [Android NetworkCapabilities](https://developer.android.com/reference/android/net/NetworkCapabilities#NET_CAPABILITY_VALIDATED).

## Проверка

Регрессионные тесты исполняют ту же чистую политику выбора сети, что использует Android-код. Проверены сеть без VALIDATED, предпочтение проверенной сети, выбор активной сети при равенстве, исключение VPN, локальная сеть без INTERNET, потеря только валидации и отсутствие сети. 105 Core-тестов прошли, включая 7 новых.

8 октября 2026 года собран подписанный Release ARM64 APK 0.5.21 (50021). Проверены minSdk 27, targetSdk 36, ABI arm64-v8a, подписи v2/v3 текущего сертификата и zipalign с выравниванием 16 КБ. Встроенный AWG совпадает с пересобранной библиотекой для API 27; среди нативных библиотек с отметкой Android API нет требования выше 27. В компиляции нет предупреждений CA1416. APK и SHA-256 для передачи: artifacts/android-0.5.21/. Владелец проверил на телефоне: выбор сети больше не запрещает запуск, но доступ через туннель не появился. Отдельная проверка HY2 возвращает «Недоступен», TCP-профили — таймаут; AWG не подтверждает handshake. Продолжение диагностики: [0.5.22](android-0.5.22-probe-diagnostics.md).

## Проверка владельцем

1. Полностью отключить Hiddify и другие VPN. Если другой клиент назначен постоянным VPN с блокировкой трафика без него, сначала проверить его системные настройки: Android не должен блокировать трафик Di-Tunnel правилами другого VPN.
2. Установить 0.5.21 поверх 0.5.19. Сертификат и applicationId сохраняются; удаление приложения и очистка данных не требуются при совпадении подписи.
3. В той же мобильной сети выполнить проверку одного TCP-профиля, затем HY2/AWG при наличии профилей. Попробовать подключиться и открыть сайты.
4. Если отказ сохраняется, скопировать полный текст ошибки и сообщить, исчезли ли сообщения «Нет подключения к интернету» / «Нет доступной физической сети». Ошибка таймаута или рукопожатия после исправления означает, что диагностика прошла дальше выбора сети; сама по себе она не доказывает блокировку.
5. При появлении Wi-Fi повторить проверку той же подписки в Di-Tunnel и Hiddify. Это поможет отделить проблему мобильного маршрута от общих настроек/подписки.
6. После успешного подключения проверить смену сети, повторное подключение и работу с выключенным экраном. На телефоне друга проверить, что новая политика не нарушила рабочую 0.5.20.
