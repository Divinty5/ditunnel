# Android 0.5.22: независимые проверки профилей

Неофициальная локальная сборка для диагностики. Минимум Android 8.1 / API 27, ARM64; target API 36. Общий релиз не публикуется.

## Результаты проверки 0.5.21 владельцем

- В мобильной сети исчез отказ «Нет доступной физической сети». Xray запускается, появляется системный значок VPN и зелёная кнопка, но Telegram не загружается.
- «Проверить все» показывает четыре таймаута. При отдельной проверке с отключённым VPN HY2 возвращает «Недоступен», остальные профили — таймаут. Поэтому результат общего пакета не равнозначен четырём независимо измеренным таймаутам.
- С включённым VPN Vivaldi возвращает ERR_CONNECTION_REFUSED для https://ifconfig.me/ip и https://api4.ipify.org/.
- AWG не получает подтверждение handshake за 18 секунд: `(AwgHandshake; TimeoutException) (AwgHandshake; InvalidOperationException)`.
- Hiddify с той же подпиской также не работает в мобильной сети. Wi-Fi для сравнения пока недоступен.
- На рабочем компьютере Windows 0.5.19 подписка Di-Tunnel_Windows_OIS показывает HY2 HTTPS 368 мс, WS HTTP 10986 мс, Shadowsocks HTTP 13837 мс и таймаут HTTPU. Владелец уточнил: HY2 использует тот же VPS и порт 443, но разные клиенты 3x-ui; компьютер подключён к корпоративному интернету по кабелю.

- Затем владелец проверил на Windows именно Android-подписку. В первых двух прогонах были частичные таймауты; в следующих двух все четыре профиля успешно отвечали через HTTP: Shadowsocks 512–563 мс, HTTPU 543–557 мс, WS 575–611 мс, HY2 671–678 мс. Следовательно, Android-профили способны работать, а нестабильность наблюдается и вне телефона. Постоянная ошибка ключа не объясняет эти успешные проверки, но ограничения клиента и перебои сети/сервера ещё не исключены.

Локальный VPN-интерфейс и запущенное ядро не подтверждают обмен данными с удалённым сервером. Полученные результаты не устанавливают конкретную причину: остаются ограничения мобильного маршрута/оператора, настройки устройства, конфигурация и ограничения сервера. Таймаут handshake не позволяет отличить отсутствие ответа из-за сети от отклонённой конфигурации.

## Найденная ошибка и изменение

В быстрой пакетной проверке Android `Task.WhenAll` выбрасывал исключение одного TCP-профиля до сохранения результатов остальных. Внешний catch завершал всю проверку, пропускал UDP-профили и заполнял пустые результаты словом «Таймаут».

В 0.5.22:

- Ошибки TCP-профилей превращаются в отдельные результаты. Успех соседнего профиля сохраняется; следующие пакеты и HY2 проверяются независимо.
- Сбой HTTPS-пакета или UDP-профиля не прерывает следующие проверки. При сбое общего HTTPS-helper результат относится к его пакету, отдельная успешность каждого профиля не предполагается.
- Отмена пользователем останавливает пакет, в том числе если Android сообщает о закрытом сокете вместо OperationCanceledException. Внутренний таймаут профиля не отменяет остальные проверки.
- Сообщения различают TCP-таймаут, ошибку DNS, отсутствие маршрута, ошибку подключения и ошибку самой проверки. Неполный ответ helper не выдаётся за таймаут.
- Главный статус Android уточнён: «Туннель VPN запущен». Он описывает запуск локального VPN; зелёная кнопка и системный значок не подтверждают доступ к интернету. Быстрая успешная TCP-проверка тоже подтверждает только установку TCP-соединения.
- Добавлены переводы новых сообщений. AndroidVersion 0.5.22, versionCode 50022; минимум API 27 сохраняется.

Изменение исправляет доказанную ошибку диагностики. Восстановление связи на телефоне пока не подтверждено; новые сетевые обходы и изменение серверных конфигураций не добавлялись.

## Проверка

110 Core-тестов прошли, включая пять новых сценариев: отказ одного TCP-профиля при успешном соседнем и последующей UDP-проверке, внутренний таймаут, отмена пользователя при закрытии сокета, отказ запуска после отмены и синхронная ошибка подготовки.

Также прошли 107 тестов интерфейса, включая существующие проверки локализации и обработки результатов.

После установки проверить отдельно HY2 и TCP-профиль с отключённым VPN, затем «Проверить все». Результаты отдельных и общих проверок должны согласовываться; успешные проверки не должны теряться из-за соседнего отказа. Для проверки связи использовать сайты и приложения после подключения. При возможности сравнить тот же HY2 endpoint в другой сети или через другую SIM, не меняя профиль. Это позволит отделить мобильный маршрут от конфигурации и устройства.

Собран подписанный ARM64 APK 0.5.22 (50022). Проверены minSdk 27, targetSdk 36, подписи v2/v3 прежнего сертификата, zipalign 16 КБ и нативный AWG API 27. В компиляции нет предупреждений CA1416. Передаваемый APK и SHA-256 находятся в artifacts/android-0.5.22/. Проверка этой сборки на телефоне ещё не выполнялась.
