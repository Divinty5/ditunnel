# Интеграция AmneziaWG

Актуализировано 5 октября 2026 года. Windows и Android 0.5.13 используют общий SOCKS-мост и конвертер параметров; системная интеграция платформ различается. [Проверка реализации и оставшиеся задачи](amneziawg-support-review.md) отделяет реализованные функции от подтверждённых системных гарантий.

## Общий backend

```text
приложение → системный TUN → Xray / правила → SOCKS5 на loopback → AWG netstack
                                                                 ↓
                                                защищённый UDP → AWG-сервер
```

AWG не создаёт второй системный адаптер. Go-мост принимает TCP CONNECT и UDP ASSOCIATE только на `127.0.0.1`, с обязательными случайными логином и паролем для каждой сессии. Назначения передаются netstack закреплённого официального ядра AWG; при отказе нет прямого fallback. Xray сохраняет доменные/IP-правила и блокировку рекламы; Android дополнительно использует списки приложений VpnService.

Ядро закреплено на commit `b5928efb6ca19f0153958460c3d141f04abc5c2e`, module version и checksum записаны в `eng/amneziawg-runtime.json`, зависимости — в `runtime/amneziawg/go.mod` и `go.sum`. Windows toolchain — Go 1.27.1. Android toolchain/NDK закреплены отдельно в `eng/android-runtime.json`.

## Импорт и параметры

Клиентский `.conf` с `[Interface]` и одним `[Peer]` импортируется из буфера, ручного ввода, Base64 и HTTPS-источника. На Windows доступен импорт из файла. `vpn://` декодируется из Base64URL и Qt qCompress: длина и распаковка ограничены 2 МБ, дубликаты JSON-полей отклоняются. Используются контейнеры `amnezia-awg`, `amnezia-awg2`, `amnezia-awg-legacy` с готовым `last_config`; встроенный `.conf` либо структурированные клиентские поля преобразуются в общий профиль.

Сохраняются ключи, PSK, Address, Endpoint, DNS, MTU, AllowedIPs, keepalive, J/S/H/I и поддержанные параметры AWG 3/3.1. `AmneziaWgProfileConverter` переводит ключи Base64 в UAPI hex. Версия из экспорта сохраняется; эвристика по полям используется при её отсутствии. Окончательную проверку параметров выполняет закреплённое ядро, а совместимость с сервером подтверждает реальное соединение.

DNS-шаблоны `$PRIMARY_DNS` и `$SECONDARY_DNS` подставляются только в DNS-поле из `dns1`/`dns2`, с резервными `1.1.1.1`/`1.0.0.1`. DNS suffix не используется. DNS-резолверы и контрольные адреса должны входить в AllowedIPs. При отсутствии IP-резолверов выбирается пара Cloudflare поддерживаемого семейства. В TUN передаются только DNS, доступные по Address и AllowedIPs; отсутствие пригодного DNS даёт явную ошибку до запуска туннеля.

Не поддержаны plain WireGuard без параметров AWG, `awg://`, несколько Peer, командные хуки, неизвестные поля и API/серверный доступ Amnezia без готовой клиентской конфигурации.

## Windows

`WindowsAmneziaWgRuntime` проверяет бинарник по SHA-256 и конфигурацию через `-validate` без транспортных сокетов. Проверка выполняется до переключения работающего VPN. Сессионные конфигурации защищены ACL текущего пользователя/SYSTEM; в аргументах процесса находятся путь и PID владельца, не ключи.

Отдельный сетевой модуль C# запускается с UAC и управляет `Network/WindowsTunnelHost`. Host устанавливает маршрут внешнего endpoint через физический uplink, привязывает UDP AWG к его IPv4 и индексу интерфейса, получает SOCKS-порт через readiness-файл и запускает Xray/Wintun. Для loopback outbound AWG физический `sendThrough` не задаётся. Маршруты, DNS/NRPT, WFP и очистка принадлежат общему host; AWG наблюдает за владельцем и завершает работу при его потере.

Внешний endpoint Windows пока только IPv4. Внутренний IPv6 требует Address/AllowedIPs соответствующего семейства и поддержки сервера. В Windows 0.5.9 TUN назначает адреса только поддерживаемых семейств; неподдерживаемое семейство перехватывается и блокируется Xray до split-правил, включая режим «Только выбранные». Проверки запуска и DNS используют пригодное семейство. Полный прогон профиля только IPv4 в браузерах с предпочтением IPv6 остаётся задачей; системные доменные split-маршруты Windows пока разрешаются только в IPv4.

Быстрая проверка ждёт удалённого TLS-рукопожатия с контрольным IP, точная — HTTPS-запроса. Активный AWG-профиль проверяется через действующий мост без второго ядра с тем же ключом. Другие проверки используют временные сессии; проверки AWG одного endpoint сериализуются. Современный host реализован на C#, тесты системных операций используют подменённый сетевой слой.

## Android

`DiTunnelVpnService` создаёт единственный системный TUN. В `:vpn` загружается libXray, в связанном `:awg` — отдельный Go runtime AWG. Два Go runtime не загружаются в один процесс. Конфигурация передаётся через Messenger IPC в неэкспортируемую службу; сессионный JSON с ключами не записывается на диск открытым текстом. Последний полный запрос для восстановления хранится отдельно, зашифрованным Android Keystore, в NoBackupFilesDir; удалённый профиль не восстанавливается из старой копии.

Android создаёт UDP-сокет, вызывает `VpnService.Protect` и привязывает его к физической Network на управляемом потоке. Go получает и дублирует готовый дескриптор через ABI 3; обратного вызова в Mono из Go нет. Внешний endpoint может быть IPv4/IPv6. После отключения служебные процессы завершаются вместе с TUN и сокетами.

В 0.5.9 адреса/маршруты TUN объявляются только для семейств, имеющихся и в Address, и в AllowedIPs; DNS неподдерживаемого семейства исключается. Это устранило подтверждённый NetLog сбой Vivaldi на chatgpt.com у профиля IPv4. Неподдерживаемое семейство не разрешается обходить VPN через физическую сеть.

Подключение ждёт свежего handshake до 18 секунд, общий предел запуска — 30 секунд. Отдельный `:awgprobe` не создаёт системный TUN: быстрая проверка измеряет handshake, точная выполняет HTTPS через SOCKS. Активный профиль проверяется HTTPS через сеть VPN. Измерение handshake включает запуск ядра и не является RTT. Отмена, плитка и виджеты используют общий движок.

В Android 0.5.10 включена поддержка системного Always-on VPN. Сервис использует Sticky и восстанавливает последнюю конфигурацию из хранилища, зашифрованного Android Keystore, без зависимости от открытого интерфейса. Перезапуск после потери служебного процесса и смены сети реализован; автозапуск после перезагрузки требует включённого системного Always-on. Блокировку трафика во время восстановления обеспечивает системная настройка «Блокировать соединения без VPN», а не Sticky. Возврат после потери сети подтверждён в Android 0.5.12; reboot, lockdown и расширенные сценарии без UI требуют проверки на телефоне: [порядок ручной проверки](awg-manual-validation.md). Выбор handshake учитывает доступное семейство и пропускает все локальные адреса, оставаясь в AllowedIPs. Подробнее: [протоколы и управление Android](android-controls-and-protocols.md).

## Совместная работа клиентов

Одновременное использование одного клиентского ключа AWG разными клиентами может переключать endpoint Peer между ними. Для независимых клиентов нужны отдельные клиентские конфигурации. Kill switch другого VPN может блокировать физический транспорт DT; маршруты не отменяют запрет WFP. Di-Tunnel не меняет защиту стороннего клиента и не создаёт автоматически цепочку VPN.

## Проверки и выпуск

На 5 октября 2026 года пройдены 306 C#-тестов, Go-suite и `go vet` с реальными локальными AWG 1/1.5/2/3/3.1, IPv4/IPv6, DNS, TCP/UDP, большими TLS-данными и установленным Xray. Пользователь подтвердил AWG 2.0 на Android 16, обе проверки, VPN-выход, блокировку рекламы, плитку/виджеты и исправление IPv6 в 0.5.9. В Windows 0.5.11 подтверждены обход и проксирование Vivaldi, включая AWG 2.0; в Android 0.5.12 — восстановление после потери сети и открытие приложения долгим нажатием плитки.

Остаются отдельные прогоны AWG 1/1.5/3/3.1 на устройствах и реального IPv6, DNS-утечек, сна, смены физической сети, длительной работы, отказа каждого ядра и восстановления. Старые системные проверки Xray не доказывают эти сценарии для нового AWG backend. Полная матрица и результаты: [проверка поддержки](amneziawg-support-review.md), [Windows TUN validation](windows-tun-validation.md), [Android validation](android-release-validation.md).

Для Windows используется `scripts/Build-AmneziaWG.ps1 -Test`. Android workflow, SDK/NDK, ключи, APK и диагностические журналы находятся в игнорируемом `.tools/android-build-local`; публичный `scripts/Build-Android.ps1` принимает подготовленные runtime. Лицензии и происхождение сторонних компонентов включаются в установщик/APK.

Источники закреплённого кода: [AWG](https://github.com/amnezia-vpn/amneziawg-go/tree/b5928efb6ca19f0153958460c3d141f04abc5c2e), [UAPI](https://github.com/amnezia-vpn/amneziawg-go/blob/b5928efb6ca19f0153958460c3d141f04abc5c2e/device/uapi.go), [netstack](https://github.com/amnezia-vpn/amneziawg-go/blob/b5928efb6ca19f0153958460c3d141f04abc5c2e/tun/netstack/tun.go).
