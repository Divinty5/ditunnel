# Windows 0.6.8, Android и Linux 0.6.7

База включает офисный коммит `7cb90be`: заголовки User-Agent и Accept импорта подписок сохранены. Артефакты собираются локально; публикация на GitHub не выполнялась. Сборки с теми же номерами обновлены 9 ноября 2026.

## Поведение

- Во время проверки «Остановить проверку», а во время подключения «Отменить подключение» занимают один и тот же блок вместо двух кнопок запуска. Обе кнопки приглушённого красного цвета. При пересечении внешнего статуса подключения с проверкой приоритет отдаётся отмене подключения. Высота блока сохраняется и при открытии страницы с уже начавшимся подключением. Прокрутка серверов остаётся доступной.
- У результатов одинаковые короткие причины ошибок и цветовая шкала задержки. Полный отчёт содержит платформу, версию, метод, этап, время и категорию ошибки. Ключи, подписочные URL и исходные тексты исключений в эти поля не записываются.
- На главном экране видна первая строка сообщения; кнопка копирования сохраняет подробности. Сведения об успешном запуске TUN не превращаются в подтверждение HTTPS.
- Уведомление ручного обновления подписок принадлежит общей оболочке приложения и остаётся поверх навигации. До четырёх источников обновляются параллельно; каждому даётся 10 секунд на перенаправления, заголовки и тело. Неудачный источник сохраняет предыдущий список. Начальное автоматическое обновление по-прежнему тихое.
- Достоверные метаданные `Subscription-Userinfo` блокируют новое подключение при истёкшем времени или израсходованном трафике. Отсутствующие сведения и неудачный HTTPS-запрос не трактуются как истечение. Неограниченный `total=0` не считается нулевым остатком.
- Остаток 0 дней или 0 ГБ красный; 1–6 дней и положительный остаток менее 10 ГБ жёлтый. От 7 дней и от 10 ГБ используется обычный цвет темы. Квоты обновляются после обновления подписок и по таймеру; объём остаётся последним сообщённым провайдером.

## Что унифицировано и что сохранено

| Область | Общее | Различия |
| --- | --- | --- |
| Точная проверка | `https://1.1.1.1/cdn-cgi/trace`, резерв `https://www.gstatic.com/generate_204`; резерв после отказа или через 600 мс; до 3 секунд на запрос | Android объединяет до пяти профилей в один временный Xray; Windows и Linux сохраняют отдельный процесс и собственный обход маршрутов/защиты |
| Быстрая проверка | Короткая подпись метода и цвет задержки | Android TCP проверяет доступность узла, не авторизацию; Windows/Linux HTTP через профиль, для AWG — TLS через SOCKS. Эти различия сохранены, чтобы не сломать проверки при активном туннеле/kill switch |
| Активный туннель | Подробности доступны для копирования, ошибки краткие | Android проверяет HTTPS через сам VPN. Windows сохраняет свою TCP-проверку маршрута через TUN. Linux подтверждает запуск ядра/маршрутов, последующая проверка отдельного профиля не доказывает прохождение через системный TUN |
| Защита | Нет вывода секретов в новую диагностику | Windows WFP/NRPT и Linux nftables/марки/служба не заменяются общим сетевым кодом |

Linux D-Bus-протокол повышен до 3 для передачи структурированной диагностики. Обновлять нужно весь deb-пакет; смешивание старой службы и нового интерфейса не поддерживается.

## OpenVPN на Windows

При выключенном kill switch транспорт известных процессов OpenVPN направляется через отдельный freedom-выход с привязкой к физическому интерфейсу. Правило не исключает весь UDP/1194 или произвольный корпоративный IP. Специальные маршруты корпоративного VPN сохраняются; собственные DNS-настройки и DNS-маршруты DT освобождаются при появлении другого VPN и восстанавливаются после его отключения. Чужие WFP-фильтры и DNS-политики не удаляются.

В документации [OpenVPN 2.7](https://openvpn.net/community-docs/community-articles/openvpn-2-7-manual/) `block-outside-dns` описан как блокировка DNS вне VPN средствами WFP. Это согласуется с присланным журналом, но не доказывает единственную причину конфликта. Привязка выхода проверена по [исходному коду Xray 26.3.27](https://github.com/XTLS/Xray-core/blob/v26.3.27/transport/internet/sockopt_windows.go); правило процессов — по [документации маршрутизации Xray](https://xtls.github.io/en/config/routing.html).

Проверки кода используют вымышленные адреса и подменённую сеть. Основная система агентом не переключалась между VPN, настройки корпоративного VPN не изменялись. 9 ноября пользователь подтвердил работоспособность в обоих порядках включения: DT поверх корпоративного OpenVPN и OpenVPN после DT. Это подтверждение конкретного сценария пользователя. Режим совместимости не включается при активном kill switch DT.

## Заголовок Windows, дополнение 9 ноября

По сообщению пользователя на Windows 10 Pro 22H2 (19045.6456) при переключении темы заголовок обновлялся с задержкой, системные кнопки переставали быть видны. Возможной причиной было назначение всей рамке `DarkMode_Explorer`, предназначенного для другого набора визуальных стилей.

Повторная проверка пользователя показала, что сброс `SetWindowTheme` и перерисовка DWM не устранили проблему на рабочем Windows 10. Поэтому для Windows 10 (сборки 19041–21999) добавлен собственный заголовок Avalonia: цвета меняются вместе с темой приложения, кнопки рисуются самим приложением. Сохранены системная рамка изменения размера, перетаскивание, двойной щелчок, системное меню, Alt+Space/Alt+F4 и обычная обработка закрытия/скрытия в трей. Заголовок следует текущему экрану и языку. Windows 11 сохраняет нативный заголовок; Linux не менялся.

Режим `DiTunnel.Icon.Smoke --managed-caption` проверил восемь переключений глобальной темы, немедленные цвета, геометрию всех трёх значков, привязку заголовка, сохранение размеров и активного окна, отмену закрытия обычным обработчиком. Проверен настоящий MainWindow с принудительно включённым заголовком Windows 10; изолированная оболочка прошла навигацию и сценарии отмены при ширине 900 и 400. Светлый и тёмный варианты просмотрены на снимках.

Регрессия `--window-chrome` на Windows 11 также пройдена. Физической Windows 10 здесь нет; окончательное подтверждение требуется на рабочем ПК.

## Оформление установщика

Общий `installer/Branding.iss` задаёт тёмное оформление Inno Setup 6.7+, логотип и чёрно-фиолетовый фон. Окно выбора языка и диалоги используют тот же тёмный стиль. Фон воспроизводится скриптом `scripts/New-InstallerArtwork.ps1`, без внешних шрифтов и загрузок. Проверены выбор языка, задачи, сводная страница и выход на безопасном макете с тем же include, без файлов, реестра и сетевых действий. Логика установки, восстановления сети и удаления не менялась.

## Проверка сборок

- Core: 189 тестов; Infrastructure.Xray на Linux: 101 тест с фактически упаковываемым Xray (Windows-специфичные runtime-сценарии на Linux возвращаются без выполнения).
- App на Windows и Linux: 157 тестов, включая подтверждённое исчерпание, цвета, сокращение видимого отчёта, изоляцию исключения соседнего профиля и параллельное обновление источников с сохранением неудачного.
- Platform.Linux: 80 тестов, включая отказ старых версий протокола и валидацию входных запросов при текущей версии 3.
- Windows: 100 тестов с подменённой сетью, без изменения системных маршрутов/DNS/WFP.
- Изолированный Avalonia-интерфейс: ширина 900 и 400; положение фильтра до и после запуска проверки или подключения совпадает, в том числе при первоначальном открытии во время подключения; отмена и остановка одного цвета, при отмене повторное нажатие блокируется; уведомление видно в подписках и настройках. Снимки содержат только вымышленные профили.
- На реальном Windows Xray отдельно прошёл loopback-тест `ActualXrayRoutesMatchingWindowsExecutableName`, использующий сопоставление по имени процесса, как новое правило OpenVPN. Предыдущее ограничение теста сопоставления по полному пути `ProcessRoutingRuntimeTests(match: true)` описано в [проверке Android 0.6.6](release-0.6.6-android.md); оно не объявляется исправленным этим тестом.
- Полная системная проверка VPN, сна Huawei и взаимодействия с корпоративным OpenVPN этим набором не заменяется.
- Устранена гонка самого DNS runtime-теста: UDP-запрос повторяется до готовности слушателя под прежним общим сроком 12 секунд; все проверки содержимого A/AAAA и отсутствия IPv6-запроса к upstream сохранены.

## Артефакты и упаковка

- `artifacts/installer/Di-Tunnel-0.6.8-Setup-x64.exe` — самодостаточный установщик Windows x64.
- `artifacts/android/0.6.7/Di-Tunnel-0.6.7-arm64.apk` — ARM64, версия 0.6.7/60007, минимум API 27; проверены прежний сертификат подписи и выравнивание 16 КиБ.
- `artifacts/linux/0.6.7/Di-Tunnel-0.6.7-linux-amd64.deb` — Ubuntu 24.04 amd64, интерфейс и сетевой модуль с собственным .NET и проверенным runtime.

У каждого файла есть соседний `.sha256`. Linux-пакет прошёл `Test-LinuxPackage.py`: версия, контрольная сумма, ELF-файлы, root-владение, отсутствие записи для группы/остальных, whitelist D-Bus и синтаксис установочных скриптов. Для сборки из WSL временная упаковка перенесена с Windows-диска в Linux `/tmp`: Windows-mount не сохранял режимы Unix, и dpkg корректно отклонял права 777.

Windows-отчёт о запуске TUN не помечает TCP-ответ подтверждённой авторизацией профиля. Для такого подтверждения нужны прикладная проверка через профиль и отдельный результат её метода.
