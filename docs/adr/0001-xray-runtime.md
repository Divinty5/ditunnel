# ADR 0001: закрепление Xray-core и управление процессом

- Статус: принято
- Дата: 5 сентября 2026 года
- Актуализировано: 13 сентября 2026 года

## Контекст

Di-Tunnel использует Xray-core как сетевое ядро. Автоматическая загрузка «последней» версии сделала бы сборку и поведение приложения невоспроизводимыми, а загрузка без проверки целостности создала бы риск подмены бинарника.

## Решение

- Для Windows x64 закреплён Xray-core `v26.3.27`.
- Для Android закреплён libXray `v26.7.28`; официальный AAR, commit и SHA-256 записаны в `eng/android-runtime.json`.
- URL и SHA-256 официального GitHub-артефакта хранятся в `eng/xray-version.json`.
- `scripts/Install-Xray.ps1` загружает архив, проверяет SHA-256 и только затем извлекает его в игнорируемую папку `.tools`.
- Бинарники Xray/libXray, GeoIP и GeoSite не хранятся в Git.
- `XrayProcessManager` перед каждым запуском вызывает штатную проверку `xray run -test -config`.
- Аргументы передаются через `ProcessStartInfo.ArgumentList`; командная строка не строится конкатенацией пользовательских значений.
- stdout и stderr доступны вызывающему коду как структурированные записи. Отображение логов в UI потребует отдельного слоя удаления секретов.

## Последствия

Обновление Xray — явное изменение манифеста с повторной проверкой совместимости HY2, TUN и конфигураций. Первая реализация завершает процесс через стандартные средства .NET и после таймаута принудительно завершает дерево процессов. Корректное взаимодействие со службой Windows и более мягкая остановка будут уточнены при создании привилегированного host.

Xray-core/libXray распространяются по MPL-2.0. Windows-установщик и Android APK используют разные закреплённые runtime из-за различий платформенной интеграции. Обновление любого runtime выполняется только через проверяемый манифест и повторную проверку TUN/VpnService, DNS и поддерживаемых профилей.
