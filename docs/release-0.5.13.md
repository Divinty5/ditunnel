# Di-Tunnel 0.5.13 — Windows и Android

Материалы для будущего общего стабильного релиза. Основные функции уже включены в `main`; PR подготовки релиза добавляет проверку файлов, регрессионные тесты обнаружения обновления и автоматическую запись Android SHA-256. Публикация релиза выполняется отдельно.

## Возможности

- Реализована полноценная интеграция AmneziaWG в VPN на Windows и Android: импорт `.conf`, Base64 и клиентских `vpn://`, подключение, проверки, TCP/UDP, доменные правила и блокировка рекламы через Xray. Реализована поддержка VMess AEAD, включая TCP, WebSocket, HTTPUpgrade и gRPC.
- Поддержаны четыре языка интерфейса: русский, английский, испанский и упрощённый китайский, включая Android-уведомления, плитку и виджеты.
- Реализовано РТ по приложениям на Windows и Android: обход выбранных, только выбранные через VPN, автовыбор и сброс галочек текущего режима. В Windows добавлены приложения Store/MSIX и Codex CLI; изменение сетевых настроек вызывает переподключение.
- Добавлена плитка быстрых настроек Android в шторке: переключение VPN, синхронизация состояния и открытие приложения долгим нажатием.
- Добавлены Android-виджеты 1×1, 2×2, 4×3, 4×4 и 4×5; большие виджеты позволяют выбирать сервер подписки.
- Исправлены отмена подключения/проверок и возврат Android VPN после потери сети. В Windows добавлены обнаружение оставшейся WFP-защиты и явное восстановление доступа к сети.
- Синхронизирована версия обеих платформ — **0.5.13**; Android versionCode — **50013**.

Полноценная интеграция протокола не означает проверку каждого варианта на реальном сервере. AWG 2.0 подтверждён пользователем; AWG 1/1.5/3/3.1 и IPv6 проверены локальным тестовым транспортом. Windows требует IPv4 внешнего endpoint. VMess поддерживается в варианте AEAD (`aid=0`). Матрица и оставшиеся проверки: [поддержка AWG](amneziawg-support-review.md), [управление и восстановление](controls-recovery-validation.md).

## Файлы для штатного обновления

Релиз должен иметь тег **`v0.5.13`** и четыре отдельных файла с точными именами:

| Платформа | Установщик | Контрольная сумма |
| --- | --- | --- |
| Windows x64 | `Di-Tunnel-0.5.13-Setup-x64.exe` | `Di-Tunnel-0.5.13-Setup-x64.exe.sha256` |
| Android ARM64 | `Di-Tunnel-0.5.13-arm64.apk` | `Di-Tunnel-0.5.13-arm64.apk.sha256` |

Каждый `.sha256` содержит одну строку: 64 шестнадцатеричных символа, два пробела и точное имя соответствующего установщика. ZIP вместо APK, общий файл checksums или другое имя установщика не подходят для текущего `ReleaseChecker`.

Сборочные скрипты Windows и Android создают отдельные `.sha256`. Перед загрузкой проверить реальные файлы:

```powershell
./scripts/Test-ReleaseAssets.ps1 `
    -WindowsInstaller ./artifacts/installer/Di-Tunnel-0.5.13-Setup-x64.exe `
    -AndroidApk ./.tools/android-build-local/releases/0.5.13/Di-Tunnel-0.5.13-arm64.apk
```

Оба установщика и оба `.sha256` сначала загрузить в черновик релиза, затем опубликовать его как стабильный, без признака prerelease. Для старых клиентов, использующих общий GitHub latest, общий релиз следует отметить latest. Современный клиент выбирает последнюю стабильную версию с полной парой файлов своей платформы; черновики, prerelease и неполные пары не предлагаются.

Windows скачивает и проверяет SHA-256, затем запускает установщик с подтверждением UAC. Android скачивает и проверяет APK, затем открывает системный установщик: пользователь должен разрешить установку из этого источника и подтвердить обновление. Установка не выполняется без участия пользователя.

## Подпись и проверка перед публикацией

APK 0.5.13 подписан тем же новым ключом, что предыдущие локальные 0.5.x. Он обновляется поверх этих APK. Прежний утраченный ключ использовался для старой линии Android-релизов: несовпадение подписи требует удаления старого APK, при котором теряются локальные данные. Повышение версии не устраняет несовместимость подписей. Windows-установщик пока не подписан кодовой подписью.

На основном коде прошли 306 C#-тестов, Go-suite и `go vet`; проверены локальные APK и Windows-установщик. В PR подготовки релиза добавлены четыре проверки общего релиза и неполной пары файлов; полный набор App прошёл 75/75. Скрипт проверки файлов прошёл на настоящих сборках, а также отклонил неверное имя APK, повреждённый хеш, чужое имя внутри `.sha256` и пустую checksum. Восстановление после потери сети и долгое нажатие Android-плитки подтверждены на телефоне; обход/проксирование Vivaldi, включая AWG 2.0, подтверждены на Windows.

Штатное обновление через GitHub нужно проверить после публикации: наличие файлов в PR само по себе не создаёт обновление. Android workflow, ключи и бинарники остаются вне Git. Linux пока не заявляется поддерживаемой платформой.
