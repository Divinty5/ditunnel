# Проверка поддержки AmneziaWG

Дата: 5 октября 2026 года. Подготовлены Windows и Android 0.5.13. Новые исправления требуют ручной проверки; опубликованных GitHub-релизов этих сборок нет.

## Вывод

Обновление 5 октября: текущие тестовые сборки — Windows и Android 0.5.13. Добавлены процессные правила Windows, обнаружение/явное восстановление оставшейся WFP-защиты и Android foreground-контроллер возврата сети. Автоматически проверены 306 C#-тестов. РТ Vivaldi на Windows и возврат сети на Android подтверждены пользователем; аварии, reboot и lockdown ещё требуют [ручной проверки](controls-recovery-validation.md). Доступен реальный профиль AWG 2.0; другие версии и IPv6 пока проверены только на локальном тестовом транспорте.

AmneziaWG реализован как рабочий backend на Windows и Android. AWG 2.0 проверен пользователем на реальном Android-телефоне, включая исправление IPv6 в 0.5.9. Ревизия выявила и устранила ошибки выбора handshake/DNS, адресов TUN Windows и отмены операций. Добавлено сервисное восстановление Android без открытого UI и запуск системного Always-on. Завершённую поддержку всей матрицы AWG и системных гарантий пока заявлять нельзя: полные сценарии аварий, reboot, lockdown и других версий AWG ещё не проверены на устройствах.

## Проверенные пути кода

| Возможность | Реализация и граница |
| --- | --- |
| Импорт | `AmneziaWgConfiguration`, `AmneziaVpnLink`, `ProfileParser`: один Peer, `.conf`, Base64, клиентские `vpn://`, ограниченная распаковка и проверка полей. Командные хуки не выполняются. |
| Параметры AWG | `AmneziaWgProfileConverter`: ключи, PSK, J/S/H/I, параметры AWG 3/3.1, MTU, DNS и AllowedIPs передаются закреплённому официальному ядру. Версия из экспорта сохраняется; определение версии по полям не проверяет сервер. |
| TCP/UDP | Общий Go-мост: SOCKS5 с обязательной аутентификацией на loopback, TCP CONNECT и UDP ASSOCIATE через AWG netstack, без прямого fallback при отказе AWG. |
| Windows | `WindowsVpnEngine`, `WindowsAmneziaWgRuntime`, `Network/WindowsTunnelHost`: проверка ядром, привязка внешнего UDP к физическому IPv4, Wintun/Xray, собственные маршруты/DNS/WFP, наблюдение за процессами и очистка. |
| Android | `DiTunnelVpnService`, `DiTunnelAwgService`, `AndroidAmneziaWgRuntime`: один системный TUN, libXray в `:vpn`, AWG в `:awg`; UDP защищён и привязан к физической сети до передачи дескриптора Go. |
| Проверки серверов | Windows: TLS либо HTTPS через AWG; Android: свежий handshake либо HTTPS через отдельный `:awgprobe`. Активный профиль проверяется через действующий туннель. Ожидание ограничено и отменяется. |
| Правила | Xray сохраняет блокировку рекламы и доменные/IP-правила. Android применяет списки приложений через VpnService.Builder; Windows — правила Xray по точным путям процессов после захвата трафика TUN. Неподдерживаемое семейство блокируется раньше split-правил. |
| Отмена | Windows/Android используют фиксированную панель над списком подписки. Отмена подключения остаётся видимой до окончания очистки, даже после раннего события Disconnected. |
| IPv4/IPv6 | Семейство должно присутствовать в Address и AllowedIPs. Handshake пропускает локальные адреса; DNS фильтруется также по маршрутам Peer. Windows назначает только поддерживаемые адреса, сохраняя перехват неподдерживаемого трафика для блокировки. |
| Восстановление Android | Sticky-сервис хранит последний полный запрос зашифрованным Android Keystore, исключённым из backup. Удалённый профиль не восстанавливается. Сервис наблюдает физическую сеть и пересоздаёт AWG после смены привязки или потери процесса. |
| Always-on Android | Метаданные включены. Системный запуск восстанавливает сохранённый запрос без UI. После reboot нужен Always-on в ОС; блокировку прямого трафика при отсутствии туннеля обеспечивает отдельно включённый системный lockdown. Reboot и lockdown требуют проверки на устройстве; обычный возврат сети подтверждён. |

## Автоматическая проверка

- `DiTunnel.Core.Tests`: 98 тестов, включая импорт AWG и `vpn://`.
- `DiTunnel.Infrastructure.Xray.Tests`: 85 тестов, включая UAPI, пригодный handshake/DNS, блокировку неподдерживаемого семейства до split-правил, SOCKS/TLS и реальные локальные VMess TCP/WS/HTTPUpgrade/gRPC.
- `DiTunnel.App.Tests`: 71 тест, включая отмену при раннем Disconnected и задержанной очистке, отложенные проверки, выбор серверов и локализацию.
- `DiTunnel.Platform.Windows.Tests`: 52 теста с подменёнными системными операциями; проверены адреса и маршруты неподдерживаемого семейства во всех трёх split-режимах и их очистка.
- Go: `go test ./... -count=1 -timeout 180s` пройден закреплённым Go 1.27.1. Проверены реальные локальные AWG 1/1.5/2/3/3.1, IPv4/IPv6 TCP/UDP, DNS внутри AWG, аутентификация, отсутствие fallback, большие TLS-запросы и композиция с установленным Xray.
- `go vet ./...` пройден.

Всего пройдено 306 C#-тестов на текущем коде. TLS-тесты используют локальную цепочку доверия без загрузки сертификатов из сети; недоверенный сертификат проверяется отдельным отрицательным тестом. Нативные Xray runtime-тесты изолированы от параллельной нагрузки. Тест конфликта портов выбирает пригодный TCP-порт и ждёт фактическую ошибку UDP/ненулевой выход процесса. Итоговый прогон Xray прошёл 85/85; прежние тайм-ауты сохранены в локальной диагностике. NuGet сообщил о недоступности сервиса проверки уязвимостей: успешные тесты не подтверждают отсутствие актуальных уязвимостей зависимостей.

Транспортные тесты используют loopback и синтетические ключи; системные маршруты и работающие VPN пользователя не изменялись. APK и установщик собраны локально. Android API/VpnService, Always-on, смена сети и реальные WFP/NRPT этим набором не проверяются.

## Подтверждено на устройствах

- Windows 0.5.8: пользователь подтвердил установку, подключение AWG и открытие chatgpt.com в Vivaldi. Локальная диагностика также получила HTTPS-ответы через AWG по HTTP/1.1 и HTTP/2.
- Android 16 ARM64, Xiaomi: импорт `vpn://` AWG 2.0, handshake, HTTPS-проверка, VPN-выход, Telegram/X, реклама Hornet, автовыбор Vivaldi/Mobifitness, синхронизация плитки и виджетов.
- Android 0.5.9: повторный NetLog подтвердил два HTTP 200 для chatgpt.com через HTTP/2, девять TLS 1.3 соединений по IPv4 и отсутствие `ERR_CONNECTION_CLOSED`. Пользователь подтвердил отправку письма. Это проверка конкретного профиля, а не всей матрицы AWG.
- Windows 0.5.11: подтверждены обход/проксирование Vivaldi, смена IP и переподключение при изменении приложений; РТ также проверено с AWG 2.0. Android 0.5.12: подтверждены установка, восстановление после потери сети и открытие приложения долгим тапом.

## Границы и оставшиеся проверки

1. Windows требует IPv4 endpoint. Внутренний IPv6 требует соответствующих Address/AllowedIPs и маршрутизации сервера. Доменные split-маршруты Windows разрешаются только в IPv4; полный паритет IPv6 split ещё не реализован.
2. Один Peer; нет plain WireGuard, `awg://`, командных хуков и подписок управления Amnezia без готовой клиентской конфигурации. DNS suffix не используется. DNS и контрольные адреса HTTPS должны входить в AllowedIPs; handshake сам по себе не доказывает интернет-доступ.
3. AWG 1/1.5/3/3.1 и IPv6 проверены локальными синтетическими соединениями, но требуют отдельной проверки на телефоне и реальном сервере. У пользователя сейчас доступен только AWG 2.0.
4. В Android 0.5.12 пользователь подтвердил восстановление после потери сети; reboot, системный lockdown и расширенные сценарии без процесса UI ещё требуют проверки. Sticky не гарантирует немедленный перезапуск OEM и не блокирует прямой трафик. Принудительная остановка приложения в системных настройках отличается от аварии процесса и может требовать ручного запуска.
5. Требуются проверки DNS/IPv6-утечек, сна, длительной работы, потери/смены сети и аварии каждого ядра. Старые Windows VM-результаты и Android 0.4.24 не подтверждают новый backend. Корпоративный антивирус и kill switch другого VPN могут блокировать операции.
