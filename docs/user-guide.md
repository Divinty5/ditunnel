# Руководство пользователя Di-Tunnel

## Подписки и профили

Кнопка **+** импортирует отдельный сервер или подписку. HTTPS-подписки принимаются как обычный текст или Base64 со ссылками на профили. Запрос передаёт идентификатор DiTunnel и признак совместимости с форматом v2rayN. Если провайдер возвращает вместо серверов сообщения об истечении срока или лимите устройств, проверьте условия подписки у провайдера.

В меню **Подписки и профили** одно нажатие выбирает строку для проверки, отправки или удаления. Двойное нажатие либо удерживание выбирает профиль и сразу подключает VPN или переключает действующий туннель. Активный и выбранный профили могут быть разными. Жёлтый означает переходное состояние, зелёный — подтверждённое подключение, красный — ошибку, фиолетовый — отключение. Во время подключения и проверки соответствующая кнопка отмены появляется на месте кнопок проверки. На Android плитка и виджеты отражают состояние фактически запущенного туннеля. [Плитка и виджеты Android](android-controls-and-protocols.md#плитка-и-виджеты).

Кнопки обновления работают с выбранной подпиской или со всеми подписками. По умолчанию запрос проходит через действующий VPN. **Настройки → Соединение → Обновлять подписки напрямую** отправляет эти запросы через физическую сеть. Включённый kill switch на Windows и Linux может блокировать этот путь.

Кнопка удаления сервера запрашивает подтверждение. **Недоступные** удаляет профили с результатом проверки, по которому они признаны недоступными. При удалении одиночного ручного сервера этой кнопкой тоже запрашивается подтверждение. Подписка со ссылкой сохраняется даже после удаления последнего сервера, поэтому её можно обновить или поделиться ею. Неоконченная проверка сохраняет профиль.

## Протоколы и форматы

Xray поддерживает VLESS, Hysteria 2, Trojan, Shadowsocks SIP002 и VMess AEAD. Набор транспортов зависит от протокола и платформы. Для VMess принимаются Base64 JSON-ссылки `vmess://` с `aid=0`. Импорт учитывает шифрование, SNI, ALPN и TLS fingerprint. Произвольный Xray JSON можно импортировать и хранить.

AmneziaWG принимает клиентские конфигурации `.conf`, Base64 и ссылки AmneziaVPN `vpn://` с готовой конфигурацией. На Windows доступен импорт из файла. Поддерживается один Peer. Импорт отклоняет конфигурации plain WireGuard, командные хуки и неизвестные поля. На Windows внешнему endpoint AWG нужен IPv4. Linux поддерживает ограниченный набор конфигураций, а для каждой вариации AWG и IPv6 важна матрица проверок. Hysteria 2 использует UDP/QUIC. [AmneziaWG](amneziawg-support-review.md) · [Протоколы Android](android-controls-and-protocols.md) · [Границы поддержки Linux](linux-installation.md#границы-поддержки).

## Раздельное туннелирование

В настройках доступны **Всё через VPN**, **Обход выбранных** и **Только выбранные через VPN**. Домены и IPv4-адреса вводятся по одному в строке. URL преобразуется в имя хоста, кириллические домены автоматически преобразуются в Punycode для маршрутизации. Например, `ru` и `рф` в режиме обхода охватывают соответствующие зоны и их поддомены.

Windows обнаруживает установленные и запущенные приложения и позволяет добавить `.exe` вручную. Android использует список установленных приложений. Ubuntu ищет исполняемый файл по ярлыку, включая известные ярлыки Snap и Flatpak. Для нестандартных оболочек и отдельных сетевых пространств имён требуется проверка. Сброс выбора относится к текущему режиму. [Ubuntu](linux-installation.md#автозапуск-и-рабочий-стол) · [Реализация Android](android-controls-and-protocols.md) · [Защита Linux](linux-protection-stage.md).

Миграция из старых версий Windows и Android могла однократно включить режим **Обход выбранных** и заполнить список через автовыбор. Режим и список можно изменить в настройках. Если после обновления программы изменился путь к исполняемому файлу Windows, заново выполните автовыбор либо укажите путь вручную.

На Windows и Android настройка **Блокировать рекламу и трекеры** сверяет домены с локальным списком. Сервисы, которые отдают рекламу и основной контент с общих доменов, могут по-прежнему показывать рекламу. [Архитектура и данные](architecture.md).

## Защита соединения и восстановление

| Платформа | Как работает защита |
| --- | --- |
| Windows | Kill switch применяет правила Windows Filtering Platform для IPv4 и IPv6. При штатном отключении правила удаляются. После аварии блокировка может сохраниться. |
| Android | Сначала подключитесь вручную, затем включите **Постоянная VPN** в настройках Android. Для блокировки прямого трафика отдельно включите **Блокировать соединения без VPN**. |
| Ubuntu | Kill switch использует nftables и сохраняет защиту при смене сервера и восстановлении. Служба получает отдельное сетевое разрешение для проверок. |

В Windows и Ubuntu остаточную блокировку можно убрать через **Настройки → Диагностика → Восстановить доступ к сети**. Для ручного восстановления Windows при закрытом Di-Tunnel предусмотрен установленный `Repair-DiTunnelNetwork.ps1`, который администратор запускает из каталога установки. Для Ubuntu описаны команды восстановления службы. [Windows](windows-tun-validation.md#диагностика) · [Ubuntu](linux-installation.md#обновление-и-удаление) · [Проверки Android](android-release-validation.md).

## Проверка серверов и диагностика

Быстрая проверка зависит от протокола и платформы. Например, TCP-ответ подтверждает доступность узла, а AWG handshake — ответ на рукопожатие. Точная проверка выполняет контрольный HTTPS-запрос через профиль. Задержка относится к указанному методу. **Lowest** периодически проверяет серверы в подписке и выбирает доступный профиль с наименьшей измеренной задержкой. При смене сервера VPN переподключается.

**Ошибка TLS** означает, что на этапе проверки не удалось установить или подтвердить защищённое соединение. Возможны неподходящий сертификат, несовпадение имени сервера или обрыв рукопожатия. Короткий статус сам по себе не определяет причину. **HTTPS · Тайм-аут** означает, что закончился бюджет HTTPS-проверки. На Android, если завершился тайм-аутом запуск AWG до HTTPS-запроса, показан фактический этап **Handshake AWG · Тайм-аут**.

При сбое скопируйте отчёт кнопкой рядом с сообщением, чтобы сохранить этап и результат текущей попытки. Перед публикацией удалите из отчёта или скриншота адреса частных серверов, токены и другие чувствительные данные. Проверка контрольного адреса и загрузка медиа в отдельном приложении могут проходить по разным маршрутам. Для такой ошибки полезно указать, помогает ли смена сети, и проверить режим разделения трафика. [Матрица Android](android-release-validation.md) · [Проверки Windows](windows-tun-validation.md) · [Проверки в Ubuntu](linux-vm-testing.md).

## Локальные данные

Windows использует DPAPI текущего пользователя, Android — Android Keystore и внутренний каталог приложения, Ubuntu — связку ключей Secret Service. На Android локальные профили и настройки удаляются вместе с приложением. На Ubuntu пользовательские данные сохраняются при удалении системного пакета. [Политика безопасности](../SECURITY.md) · [Удаление на Ubuntu](linux-installation.md#обновление-и-удаление).
