# Проверка исправлений Linux 0.6.5

Дата: 14 октября 2026 года. Среда: изолированная Hyper-V VM с Ubuntu 24.04.5 LTS, GNOME/Mutter 46.2, XWayland. Перед проверками сохранён checkpoint. Сетевые проверки на основной Windows не проводились.

## Воспроизведение и исправления

| Наблюдение пользователя | Причина и изменение | Проверка |
| --- | --- | --- |
| Не видны цифры задержки | Длинное описание обрезалось в узкой плитке; выведено краткое число, подробности перенесены в подсказку | Проверены модель и реальная узкая плитка |
| Белый заголовок после смены темы | Заголовок рисовал оконный менеджер; в Linux включены декорации Avalonia | Светлая/тёмная темы в GNOME/XWayland |
| Закреплённый значок остаётся фиолетовым | GNOME использует значок desktop entry вместо значка окна; обновляется пользовательский themed icon с уведомлением рабочего стола | Четыре снимка одного закреплённого окна: фиолетовый → зелёный → красный → фиолетовый; проверены пиксели дока |
| Неверный маршрут выбранного браузера | В правило попадал launcher вместо реального ELF; исправлены разрешение путей и миграция сохранённых правил | Автотесты launcher и миграции; сетевые проверки описаны ниже |
| Telegram отсутствует в списке | Не учитывались экспортированные ярлыки Snap/Flatpak и `env` перед командой | Установленный Telegram Snap найден с путём к ELF в конкретной ревизии |
| После ошибки kill switch нельзя восстановить сеть | В обработчике ошибки клиент навсегда закрывал D-Bus-соединение; восстановление использовало уже закрытый объект | Ошибка воспроизведена со старой DLL 0.6.4 посредством сбоя systemd-resolved при старте и очистке. Новый клиент восстановил сеть, повторно подключился и отключился без перезапуска GUI/VM |

Операции Connect/Disconnect/Restore сериализованы, монитор состояния пропускает незавершённые операции. Ошибка очистки сохраняет возможность вызвать «Восстановить сеть» и не выдаёт отсутствие ответа за снятую защиту.

Для Flatpak путь `/app/...` преобразуется в фактический host path только при совпадении inode с исполняемым файлом процесса. В VM проверены настоящий mount namespace и ограничения службы, включая `ProtectHome=yes`; метаданные не принимаются на доверии.

## Автоматические проверки

- 448 тестов .NET на Linux: Core — 151, Infrastructure — 97, App — 128, Platform.Linux — 72.
- Тесты нативного Xray: `common/net`, `app/router`, локальные IPv4/IPv6 TCP/UDP sockets, wildcard/dual-stack, Flatpak metadata и сопоставление inode; тесты AmneziaWG runtime.
- Linux smoke: настоящий приватный D-Bus, polkit allow/deny, отмена проверки, владение сессией, восстановление после ошибок, завершение Xray/AWG.
- UI smoke: темы, границы окна, минималистичные разделы, сохранение черновиков, прокрутка серверов во время проверки, числовая задержка и цвета значка.
- Значок GNOME: проверены штатный выход, восстановление после аварийного завершения, сохранение пользовательских прав доступа и изменений собственного значка.
- На Windows дополнительно пройдены 97 тестов Infrastructure, включая готовность SOCKS listener при повторных попытках.

На установленном пакете пройдена полная сетевая матрица: отключение/восстановление/повторное подключение с IPv4-only и без него; оба режима РТ для доменов, IP и пользовательского процесса по TCP/UDP и IPv4/IPv6; Shadowsocks; авария ядра, потеря клиента, SIGKILL и SIGTERM службы; удержание KS и отсутствие утечек по packet capture; исключение LAN, отсутствие открытого DNS и сохранность чужой nftables table. Перед сохранением исходного состояния тест дожидается завершения IPv6 DAD временного peer-интерфейса.

Настоящий Яндекс Браузер из официального `.deb` проверен с отдельным временным профилем: выбранный браузер получил DIRECT в BypassSelected и VPN в ProxySelected; контрольный процесс в обоих случаях получил противоположный маршрут. Ответ читался из загруженной браузером страницы через локальный debug endpoint, поскольку `--dump-dom` у этой сборки не завершался. Флаг `--no-sandbox` использовался только для данного изолированного теста; приложение Di-Tunnel не меняет параметры запуска браузера.

В предоставленной пользователем подписке SS и Hysteria 2 ответили с числовой задержкой; два VLESS-профиля из VM не ответили. Через доступный SS-профиль пройдены два цикла реального HTTPS-трафика, отключения, восстановления и повторного подключения с подтверждённым KS. После очистки возвращался исходный прямой маршрут. Публичный IP VM не изменялся, поэтому смена публичного IP этим тестом не подтверждена; отдельная синтетическая матрица различала DIRECT/VPN на стороне сервера.

## Ограничения

GNOME обновляет кэш значков с задержкой порядка 2,5 секунды; в тесте снимки делались через 5 секунд после смены состояния. Мгновенная смена на всех Linux desktop environments не заявлена. Расширения GNOME не нужны.

Linux-трей не добавлен: доступно обычное сворачивание в панель/док; скрытие окна без возможности возврата не предлагается.

Проверены известные launchers и экспортированные ярлыки. Универсальная поддержка произвольных shell wrappers, отдельных network namespaces и всех приложений Snap/Flatpak не заявлена. Системный DNS остаётся общим. Публичный IPv6, реальный AWG handshake, suspend и смена uplink требуют отдельных проверок.

Реальная подписка использовалась только внутри VM. Её адрес, ключи, конфигурации серверов и необезличенные сетевые журналы в репозиторий не переносились.
