# Проверка Linux 0.6.6 в Ubuntu VM

Дата: 21 октября 2026 года. Проверки выполнены в выделенной Ubuntu 24.04 amd64, с systemd-resolved, nftables и GNOME/XWayland. Маршруты, DNS и firewall основной Windows не менялись.

## Исправления и результаты

| Пункт | Реализация и проверка |
| --- | --- |
| Переключение сервера при KS | Добавлен D-Bus Switch с проверкой владельца. Новый адрес разрешается до остановки старого туннеля; журнал и firewall сохраняются, правила заменяются одной транзакцией nft. Пройдены VLESS → Shadowsocks → VLESS с DNS-именем, с IPv4-only и без него; проверены HTTPS-трафик реальных профилей и смена политики KS. |
| Флаги | В Linux entry point подключён resolver локальной geoip.dat. Для всех четырёх профилей тестовой подписки получены страны; флаг выбранного сервера и флаг в списке проверены в реальном интерфейсе GNOME. Внешний сервис GeoIP не используется. |
| Проверки других серверов при KS | Добавлены временные наборы адрес/порт с отдельными TCP/UDP и IPv4/IPv6. Разрешение ограничено UID 0, cgroup службы и меткой транспорта; удаляется после проверки и истекает в ядре через 30 секунд. Пройдены синтетические HTTP-проверки неактивного сервера и быстрые/HTTPS-проверки трёх доступных реальных профилей при активном KS. |
| Повторные запросы прав | Административное разрешение переиспользуется только тем же уникальным активным D-Bus-клиентом. На настоящей приватной шине проверены первый запрос, повторное восстановление без новой интерактивной авторизации, отказ другому клиенту того же UID и сброс после исчезновения клиента. Проверки системной службы выполнялись root; первый пользовательский диалог polkit вручную не подтверждался. |
| Восстановление с KS | После принудительного завершения собственного Xray тот же клиент повторно подключился с удерживаемым KS без перезапуска, в обоих режимах IPv4. Отдельно внесены временные ошибки resolvectl при старте и очистке: RestoreNetwork и последующее подключение прошли тем же клиентом. Проверено повторное использование адреса имени после истечения обычного DNS-кэша виртуальными часами. |
| Метод рядом с задержкой | В общем интерфейсе Linux/Windows выведено, например, «428 мс · HTTP»; детальный ответ сохранён в подсказке. Проверены TCP/TLS/HTTP/HTTPS в модели, фактические HTTP/HTTPS в сетевых измерениях и ширина полного текста в узкой плитке. |

Во время интеграционного прогона обнаружено отсутствие Switch в whitelist системной D-Bus. Политика исправлена; валидатор deb теперь проверяет полный набор разрешённых методов. Последующий прогон выполнен после установки окончательного пакета.

Один внешний профиль в первом прогоне дал нестабильный HTTPS-результат, а в финальном не ответил в обоих режимах ещё до включения KS. Три остальных прошли оба режима без повторных попыток, переключение и контрольный HTTPS-трафик. Недоступность четвёртого не выдаётся за успешную проверку; данные профилей и адрес подписки в отчёт не включены.

## Регрессии

- 465 модульных тестов в Ubuntu: Core — 151, Infrastructure.Xray — 97, App — 138, Platform.Linux — 79.
- Приватный D-Bus: wire-формат polkit, allow/deny, отмена и владение проверкой, восстановление клиента после ошибок; жизненный цикл Xray и AWG helper.
- Общая сетевая матрица: оба режима РТ для доменов/IP/процесса, TCP/UDP, IPv4/IPv6, Shadowsocks, LAN, DNS, штатное отключение и восстановление, авария ядра/клиента, SIGKILL/SIGTERM службы. Проверены удержание KS, отсутствие пакетов утечки и сохранность чужой nftables table.
- Реальный executable Яндекс Браузера: BypassSelected и ProxySelected различены ответами DIRECT/VPN синтетического узла.
- GNOME/XWayland: флаг на главном экране и в списке; полный текст задержки/метода; прокрутка при проверке с блокировкой выбора; минималистичные разделы настроек, светлая/тёмная темы, черновики и цвета нативного значка. Исправлена гонка старого теста переключения сервера: изолированы выбранный сервер, ожидание завершения и очередь вызовов.
- Linux-only релиз 0.6.6: Windows/Android пропускают отсутствующие пакеты и продолжают находить предыдущую совместимую версию. Проверено также по исходникам тега v0.6.4.

Нативный runtime не менялся: переиспользованы проверенные бинарники и metadata Linux process lookup v3. Реальный AWG handshake, публичный IPv6, suspend и смена uplink в этом прогоне не проверялись. Изменение отображения метода находится также в исходниках Windows; новый установщик Windows в рамках Linux-пакета не собирался.
