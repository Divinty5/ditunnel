# Android 0.6.6

Android 0.6.6, versionCode 60006, ARM64, минимум Android 8.1 / API 27. Публикация выполняется отдельно от локальной сборки APK.

## Проверки и интерфейс

В 0.6.5 точная проверка запускала временный процесс для каждого профиля и последовательно ждала два контрольных URL. В 0.6.6 до пяти профилей проверяются параллельно одним Xray. У каждого профиля свой SOCKS-вход на loopback и свой маршрут к собственному outbound; общий маршрут по умолчанию блокирует трафик. Ошибки преобразования и DNS изолированы до запуска ядра; при отказе запуска группа разделяется на меньшие, чтобы выявить некорректный профиль и проверить остальные.

Контрольные адреса сохранены: `https://1.1.1.1/cdn-cgi/trace` и `https://www.gstatic.com/generate_204`. Бюджет каждого HTTPS-запроса — три секунды. Резервный запрос стартует после отказа основного либо через 600 мс ожидания. Первый успешный ответ отменяет оставшийся запрос. Ошибки TLS и статусы HTTP сохраняются в диагностике; проверка сертификатов не отключается.

В списке отображаются короткие результаты, например «Ошибка TLS. HTTPS не проверен» или «Тайм-аут. HTTPS не проверен». Неуспешные результаты красные и удаляются кнопкой «Отфильтровать недоступные». Это явное действие пользователя; отказ контрольного сайта сам по себе не отключает активный туннель.

Быстрая проверка показывает, например, «136 мс · TCP», с прежней цветовой шкалой задержек. Убрана дополнительная приписка о непроверенном профиле. Семантика TCP не изменилась: ответ порта не проверяет авторизацию и не подтверждает передачу данных; режим lowest не выбирает профиль только по TCP.

На главном экране оставлена короткая сводка. Версия, метод, этап, длительность, категория ошибки и результаты запросов доступны в копируемой диагностике. Исходные исключения и реквизиты доступа туда не добавляются.

## Состояние после сна

Сохранённый флаг активности больше не подтверждает живое соединение сам по себе: требуется собственный живой процесс и системная VPN Network. Плитка сверяется со статусом при открытии шторки; виджеты получают обновления при изменении VPN Network и пробуждении. Отдельный неточный `ELAPSED_REALTIME`-таймер обновляет виджеты при наличии подключения или запроса восстановления; он не будит спящее устройство и отменяется после ручного отключения или удаления виджетов. Дополнительно у провайдеров включено штатное периодическое обновление Android.

Если процесс остановлен системой, сохранённый запрос восстановления позволяет запустить VPN заново без открытия Activity, пока разрешение на VPN действительно и Android допускает фоновый запуск. Ручное отключение и отзыв разрешения этот запрос снимают. Сервис остаётся foreground/START_STICKY и явно не останавливается вместе с задачей Activity.

Подтверждены ошибки устаревшего статуса в коде, но причина долгого отключения на конкретном Huawei не установлена без проверки устройства. Android Doze может откладывать сеть и фоновую работу, а прошивка может дополнительно ограничивать процессы; постоянный wake lock не добавлялся. См. [Android: Doze и App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby), [жизненный цикл плитки](https://developer.android.com/develop/ui/views/quicksettings-tiles) и [AlarmManager](https://developer.android.com/reference/android/app/AlarmManager).

## Проверка на Huawei/HarmonyOS перед публикацией

Локальная проверка 8 ноября 2026: пройдены 175 Core-тестов, 144 теста интерфейса и три целевые проверки пакетной конфигурации, включая принятие JSON реальным Xray в режиме `-test`. Подписанный Release APK проверен сборочным скриптом: application ID, 0.6.6 / 60006, minSdk, ARM64, сертификат, выравнивание и SHA-256.

Расширенный набор Infrastructure.Xray дополнительно выявил тайм-аут Windows-теста `ProcessRoutingRuntimeTests.ActualXrayRoutesOnlyTheMatchingWindowsExecutable(match: True)`; повтор подтвердил его. Два теста конфликта локальных TCP/UDP-портов прошли при повторе. Windows-код и системные настройки не изменялись; весь расширенный набор не объявляется полностью пройденным. Эти результаты не заменяют проверку Android runtime.

ADB не обнаружил подключённых Android-устройств. Запущенный для этой проверки сервер ADB остановлен; установка APK и изменение правил брандмауэра не выполнялись. Многочасовой сон и восстановление на конкретном Huawei пока не проверены.

1. Проверить смешанную подписку: рабочий сервер, тайм-аут, TLS-ошибка и некорректный профиль. Успехи сохраняются независимо от соседних ошибок; повторная проверка не запускается для удалённых кнопкой профилей.
2. Проверить, что «Ошибка TLS. HTTPS не проверен» помещается, ошибки красные, а TCP/HTTPS-задержки имеют прежние цвета.
3. Проверить основной и резервный URL по отдельности: резерв восстанавливает результат; отказ обоих показывает короткую ошибку без выключения TUN.
4. Оставить VPN на несколько часов с выключенным экраном, затем проверить виджеты и плитку до открытия приложения. Повторить после удаления задачи из списка недавних и остановки VPN-процесса в контролируемом тесте; не использовать force-stop всего приложения как эквивалент обычного сна.
5. Проверить восстановление при смене Wi-Fi/мобильной сети, после периода без сети и после остановки процесса системой. Ручное отключение не должно включать VPN обратно.
6. Если прошивка продолжает завершать VPN, отдельно проверить разрешённую пользователем фоновую работу Di-Tunnel и системный Always-on VPN. Не менять эти настройки автоматически.
