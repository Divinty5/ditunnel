# Ручная проверка AWG 2.0 после исправлений

Текущие сборки: Windows и Android 0.5.13 (Android versionCode 50013). Пользователь подтвердил РТ Vivaldi в Windows 0.5.11, включая AWG 2.0, и восстановление/долгий тап плитки в Android 0.5.12. Следующие расширенные системные сценарии ещё требуют проверки. Дополнительные проверки сброса выбора, WindowsApps и WFP — в [сценарии 5 октября](controls-recovery-validation.md). Достаточно имеющегося рабочего профиля AWG 2.0. Ключи и ссылку `vpn://` присылать не нужно.

## Android: обычное подключение

1. После публикации релиза обновить APK штатным обновлением поверх 0.5.12, сохранив подписки. Новая 0.5.13 подписана тем же ключом. Проверить версию на главном экране.
2. Отключить другие VPN, выбрать AWG 2.0 и режим «Всё через VPN». Проверить быстрый handshake и точный HTTPS, затем подключить VPN.
3. В Vivaldi открыть ifconfig.me/ip и api4.ipify.org: ожидается IP AWG-сервера, не прямой IP телефона. Проверить chatgpt.com, отправку письма, Telegram/X и рекламу Hornet при включении/отключении блокировки.
4. Проверить «Только выбранные» с Vivaldi и «Обход выбранных» с Mobifitness. Без системного lockdown выбранное для обхода приложение должно использовать прямой путь. Повторить DNS leak test. Для профиля только IPv4 ожидается отсутствие работающего прямого IPv6 в приложениях, включённых в VPN; IPv6 внутри VPN можно проверить только с пригодным профилем и сервером.
5. Сделать пять включений/отключений. Проверить плитку и виджеты с закрытым интерфейсом и смену выбранного сервера. Проверить четыре языка, включая уведомление восстановления.

## Отмена на обеих платформах

1. В меню подписок начать проверку всех серверов и прокрутить длинный список: «Отменить проверку» должна остаться над ним. Нажать её; после завершения проверки кнопка исчезает, выбор подписки доступен.
2. Начать подключение и открыть подписки: «Отменить подключение» должна быть видна. После нажатия «Отменяем» остаётся до окончания очистки; затем снова доступен выбор подписки и запуск VPN.
3. При подключённом VPN выбрать другой сервер, затем отменить переподключение. Повторить при восстановлении после потери сети. Новые подключения не должны начинаться до завершения отмены.
4. Повторить отмену ручной проверки и текущего прохода Lowest. Если кнопка исчезла, указать платформу, версию, исходное действие, момент исчезновения и приложить снимок экрана.

## Android: восстановление и Always-on

1. Сначала успешно подключиться вручную: это сохраняет последний профиль и правила в зашифрованном хранилище.
2. Закрыть интерфейс из списка последних приложений. Плитка и виджеты должны продолжить управление; состояние должно соответствовать VPN. Принудительную остановку в системных настройках на этом шаге не использовать.
3. Переключить Wi-Fi → мобильная сеть → Wi-Fi. Включить авиарежим на 20 секунд и выключить его. Ожидается «Восстанавливаем VPN…», затем подключение к тому же профилю; после восстановления повторить IP и chatgpt.com. Проверить 10–15 минут с выключенным экраном.
4. Открыть системные настройки VPN → Di-Tunnel, включить Always-on. Затем для проверки блокировки включить «Блокировать соединения без VPN». Начать с режима «Всё через VPN»: системный lockdown блокирует и приложения, исключённые из VPN, поэтому привычный прямой обход в этом режиме ОС не ожидается.
5. Повторить потерю сети: до восстановления допускается только отсутствие доступа, прямой IP появляться не должен. Перезагрузить телефон, разблокировать его и дождаться подключения без открытия приложения. Проверить IP и состояние плитки/виджетов.
6. Если интернет не восстановился: в системных настройках сначала выключить «Блокировать соединения без VPN», затем Always-on, открыть Di-Tunnel и подключиться вручную. Сообщить версию, действие и скопированную ошибку.

Sticky позволяет ОС перезапустить службу, но время перезапуска зависит от Android/OEM. Блокировку во время отсутствия туннеля обеспечивает только системный lockdown. Force stop в настройках останавливает пакет целиком и отличается от обычной аварии служебного процесса; может потребоваться ручной запуск. Аварии `:vpn`/`:awg`, IPv6 и другие версии AWG требуют отдельного прогона с устройством/ADB и соответствующими серверами.

## Windows

1. Установить подготовленный установщик 0.5.9 вручную и проверить версию. Подтверждать только обычные запросы UAC; правила корпоративного антивируса не менять.
2. Повторить подключение AWG, IP, Vivaldi/chatgpt.com, пять циклов, три режима доменного/IP-разделения и отмену из меню подписок. После отключения сеть и DNS должны восстановиться.
3. Для IPv4-профиля проверить браузер с обычными настройками IPv6: сайт должен работать по IPv4, прямой IPv6 не должен обходить VPN в туннелируемом трафике. Отдельно проверить DNS leak test.
4. С включённым kill switch проверить потерю/возврат сети и отсутствие прямого IP до восстановления. Проверки аварий, WFP/NRPT и сна на рабочем компьютере проводить на отдельном стенде.

## Как сообщить результат

Для каждого пункта указать «прошёл» или «не прошёл», платформу/версию, профиль AWG 2.0, действие, наблюдаемый статус и время. При сбое скопировать сообщение приложения. Не присылать приватные ключи, токены подписок или необработанный сетевой журнал с личными данными в публичные Issues.
