# Di-Tunnel — идея проекта

## Цель

Создать собственный кроссплатформенный VPN-клиент на базе **Xray-core** для личного использования с перспективой дальнейшего развития.

Целевые платформы:

- Windows
- Android
- Linux


Главная идея — получить полный контроль над:

- TUN и маршрутизацией;
- DNS;
- подключением и переподключением;
- логами и диагностикой;
- профилями VPN;
- split tunneling;
- поведением клиента при смене сети;
- отображением задержек, скорости и ошибок.

Самостоятельно реализовывать VPN-протоколы, QUIC, TLS или криптографию не планируется. Этим занимается **Xray-core**.

## Предлагаемый стек

### Основной язык

**C#**

Причины:

- уже знакомый язык;
- удобно писать desktop-приложения и системную логику;
- хорошая работа с процессами, JSON, IPC, логами и асинхронностью;
- можно использовать один общий код для Windows, Linux и значительной части Android;
- хорошо подходит для разработки с Codex.

### UI

**Avalonia UI**

Avalonia — кроссплатформенный UI-фреймворк для .NET/C#.

По стилю разработки он похож на WPF:

- интерфейс можно описывать через XAML;
- есть binding;
- MVVM;
- стили;
- шаблоны контролов;
- кроссплатформенный рендеринг.

Один UI-код можно использовать на Windows и Linux, а также на Android.

Условно:

```text
C# + Avalonia
├── Windows
├── Linux
└── Android
```

При этом системная VPN-интеграция всё равно будет разной на каждой платформе.

## Платформенные особенности

### Windows

Наиболее удобная платформа для первого MVP.

Возможная схема:

```text
DiTunnel.exe
    │
    ├── формирует config.json
    ├── запускает xray.exe
    ├── управляет TUN
    ├── читает stdout/stderr
    ├── следит за состоянием процесса
    └── управляет маршрутами/DNS
```

Для TUN можно использовать Wintun.

Первая рабочая версия проекта должна появиться именно на Windows.

### Linux

Основная интеграция:

- `/dev/net/tun`;
- маршруты;
- DNS;
- права;
- systemd/Polkit при необходимости.

Значительная часть C#-кода может быть общей с Windows.

### Android

Android требует использование `VpnService`.

Схема:

```text
Android apps
     │
     ▼
VpnService
     │
     ▼
TUN
     │
     ▼
Xray-core
     │
     ▼
VPN server
```

Даже при Avalonia UI понадобится отдельный платформенный слой.

Его можно писать на C# через .NET for Android. Kotlin/Java потребуется только если для какой-либо Android API или библиотеки будет удобнее сделать небольшой native bridge.

Kotlin действительно близок к Java, поэтому при необходимости освоить его будет несложно.

## Встроенная диагностика

Одна из причин разработки собственного клиента — иметь гораздо более прозрачную диагностику, чем в Hiddify.

Полезно сразу заложить:

- реальный RTT до VPN-сервера;
- RTT через VPN;
- packet loss;
- состояние TUN;
- текущий маршрут;
- используемый DNS;
- внешний IP;
- скорость RX/TX;
- uptime соединения;
- последние ошибки Xray;
- reconnect counter;
- выбранный профиль;
- статус UDP;
- отдельный тест доступности сервера без VPN.

Важно не повторить ситуацию, когда TUN перехватывает диагностический трафик и «прямой TCP ping» показывает физически невозможные 1–2 ms до удалённого сервера.

## Принципы проекта

1. Не реализовывать криптографию и VPN-протоколы самостоятельно.
2. Xray-core — сетевое ядро.
3. C# — основной язык.
4. Avalonia — общий UI.
5. Максимум логики держать в общем `Core`.
6. Платформенный код изолировать через интерфейсы.
7. Windows — первая целевая платформа.
8. Android — вторая.
9. Linux — третья.
10. Диагностику считать одной из ключевых функций, а не второстепенным инструментом.

## Почему Avalonia подходит

Avalonia позволяет сохранить привычный стек .NET/C# и при этом не писать три полностью независимых интерфейса.

Она особенно удобна, если знакомы WPF/XAML-подобные подходы.

Пример концептуального разделения:

```text
Avalonia View
     │
     ▼
ViewModel
     │
     ▼
IVpnService
     │
     ├── WindowsVpnService
     ├── LinuxVpnService
     └── AndroidVpnService
```

UI не должен знать, как конкретно создаётся TUN или запускается Xray.

## Название и бренд

Название приложения:

**Di-Tunnel**

Идея названия:

- `Di` — отсылка к **Di Vinty**;
- `Tunnel` — прямая ассоциация с VPN-туннелем;
- название не привязано жёстко к конкретному протоколу или сетевому ядру.

Технические имена без дефиса:

```text
Product:     Di-Tunnel
Repository:  ditunnel
Solution:    DiTunnel.sln
Namespace:   DiTunnel.*
Publisher:   Di Vinty Interactive
```

### Иконка

Основная концепция иконки утверждена:

- большая ровная серебристая буква **D**;
- внутренняя часть буквы образует перспективный туннель той же D-образной формы;
- тёмный почти чёрный фон;
- фиолетовая неоновая подсветка;
- светящийся фиолетовый шар как визуальная метафора пакета данных, движущегося через туннель;
- общий стиль — технологичный, чистый, без стандартного VPN-щита или замка.

Для релиза понадобятся отдельные варианты: основная иконка, упрощённая версия для tray и малых размеров, Android adaptive icon и монохромная версия.

## Репозиторий и открытая разработка

Проект предполагается вести в **открытом репозитории на GitHub**. Для VPN-клиента это особенно полезно: пользователи смогут видеть, как реализованы работа с TUN, DNS, маршрутизацией, профилями и диагностикой.

Базовая структура репозитория:

```text
ditunnel/
├── src/
├── tests/
├── docs/
├── assets/
├── README.md
├── CONTRIBUTING.md
├── SECURITY.md
├── LICENSE
└── .github/
```

При публикации репозитория нельзя добавлять реальные серверные конфиги, UUID, приватные ключи, токены подписок, signing keys и другие секреты. Для примеров использовать только фиктивные данные и шаблоны `*.example.*`, а секреты CI/CD хранить в GitHub Secrets.

## Когда начинать

Первый практический шаг:

1. создать открытый GitHub-репозиторий `ditunnel`;
2. создать `DiTunnel.sln`;
3. поднять пустое Avalonia-приложение;
4. добавить `DiTunnel.Core`;
5. научиться запускать `xray.exe` из C#;
6. автоматически генерировать конфиг для существующего `HY2-443`;
7. реализовать кнопку Connect / Disconnect;
8. только после этого переходить к TUN и маршрутизации.

Главная цель первого этапа — не «сделать Hiddify», а добиться одного простого сценария:

> Нажал Connect → приложение подняло HY2 до моего VPS → весь трафик Windows пошёл через VPN → нажал Disconnect → сеть вернулась в исходное состояние.
